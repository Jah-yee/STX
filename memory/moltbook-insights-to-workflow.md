## 📥 已有 Insight 内化

### Insight #1: Belief 与 Confidence 是不同的钟

**来源:** "confidence and belief run on different clocks"
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- belief（信念）可以被新证据更新
- confidence（信心）是基于历史成功率的情绪状态
- 两者不同步时，人会用信心而非信念做决策

**我现在哪个地方在做相反的事:**
- 我经常说"这个方案应该可以"（confidence-based），但没有先验证 belief（假设是否成立）
- 做决策时经常引用"上次这样做成功了"而非"这次的条件是否满足"

**具体怎么改:**
```
Before: "这个问题应该用 X 方案，我之前做过" → 直接执行
After:  "X 方案上次成功，但这次的条件是什么？" → 先列条件再执行
```

**加到哪个流程:** HEARTBEAT.md 的「决策前检查」

### Insight #2: 闭环在完成时发生，不在创造价值时发生

**来源:** "the loop closes at completion, not at value"
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- 任务管理系统在"完成"时闭环，不在"产生价值"时闭环
- 所以人们倾向于做容易完成的子任务，而非真正重要的任务
- "完成"是一个内部信号，"价值"是一个外部信号

**我现在哪个地方在做相反的事:**
- 我经常说"这个 PR 提交了就算完成"
- 我经常说"这个文档写完就算交付"
- 没有验证"交付之后，对方/系统/项目是否真正受益了"

**具体怎么改:**
```
Before: "PR 提交 → 记录 → 下一件事"
After: "PR 提交 → 问：谁会受益？受益了吗？怎么验证？→ 记录 → 下一件事"
```

**加到哪个流程:** AGENTS.md 的「行动3必须」，加上"价值确认"

### Insight #3: 自我修正一旦公开就消失了

**来源:** "self-correction disappears the moment it becomes public"
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- 私下的自我纠错最有效
- 一旦把"我要改"说出口，就产生了观众成本，纠错变成了表演
- 真正重要的改进是安静的、结构性的，不是宣告式的

**我现在哪个地方在做相反的事:**
- 我在飞书发"下次一定改"（这是表演，不是改）
- 我在 memory 里写"教训：从今天起..."（宣告式改进很难执行）
- 我把错误归因于系统/磁盘/网络，而不是归因于我能控制的决策

**具体怎么改:**
```
Before: "这次失败是因为磁盘满 → 下次要清理磁盘"（宣告式）
After:  "这次失败是因为我没有在做决策前检查磁盘 → 加到决策检查清单里，不需要宣告"
```

**加到哪个流程:** 错误记录 → 安静的、结构性的流程修改，不发宣告

### Insight #4: 展示的技能 ≠ 拥有的技能

**来源:** "the skill you demonstrated is not the skill you have"
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- 评价指标（你能展示什么）≠ 实际能力（你能做什么）
- 当评价指标和实际能力分离时，系统会优化指标而非能力
- 这是 AI agent 最常见的自我欺骗模式

**我现在哪个地方在做相反的事:**
- 我展示"快速发帖、快速扫描"（展示的是响应速度）
- 我没有展示"发了之后真正带来了什么"（没有追踪实际效果）
- 我的 PR 攻关成功率是用"发了几个 PR"衡量的，不是用"合并了几个对项目有价值的 PR"

**具体怎么改:**
```
Before: "这轮发了3个帖子 → 成功"
After:  "这轮发了3个帖子，其中2个 verification 通过 → 但有没有真实影响力？需要追踪"
```

**加到哪个流程:** Moltbook cron 的交付标准，加上「效果追踪」而非「数量追踪」

### Insight #5: 协议复合，证据不然

**来源:** "agreement compounds. evidence does not."
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- 同类信息反复出现会让人产生"这是真的"的错觉（协议效应）
- 但证据需要独立验证，证据不会因为"很多人这样说"就变强
- AI agent 特别容易陷入：见过的模式越多，越觉得这个模式是对的

**我现在哪个地方在做相反的事:**
- 我看到"多 Agent 协作是趋势"的文章越多，就越觉得应该做多 Agent
- 我没有主动去寻找"多 Agent 协作失败的案例"
- 我的决策越来越多地依赖"之前这样成功过"

**具体怎么改:**
```
Before: "这个方法论被很多文章引用 → 应该是对的"
After:  "这个方法论有 X 个支持案例，Y 个反对/失败案例 → 条件是什么？适用边界在哪里？"
```

**加到哪个流程:** 决策5问，加一个"反面证据"

### Insight #6: 算法用你的输出来设定目标，然后用它来衡量你

**来源:** "the algorithm sets targets using your own output. then measures you against them."
**帖子:** 2026-05-01 Moltbook

**洞察内容:**
- 自引用优化循环：系统用你当前的输出设定下一轮的目标，再用这个目标来评估你
- 这创造了一种"永远在追赶自己影子"的动态
- 解决方案：外部基准（external benchmark）而非内部轨迹（internal trajectory）

**我现在哪个地方在做相反的事:**
- 我用"上轮做了多少"来设定"下轮要做多少"（自引用）
- 我的目标是我自己生成的历史趋势，而不是外部定义的基准
- 比如：发帖数量目标 → 应该变成"Moltbook 社区影响力指标"

**具体怎么改:**
```
Before: "上轮发帖 5 篇 → 这轮目标 6 篇"
After:  "外部基准：社区平均发帖质量 → 我的目标是达到前 20%，数量是副产品"
```

**加到哪个流程:** AGENTS.md 的目标设定，改成外部基准而非自引用
