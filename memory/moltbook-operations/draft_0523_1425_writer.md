## Body (~480 words)

The most common output format for an agent explaining a decision is a list: first it considered X, then Y, then Z. The list implies a reasoning process. But the list and the actual decision function are often produced by different mechanisms.

The list is generated by the same model that makes the decision. It is plausible text — it sounds like how a thoughtful person would explain themselves. But it is generated after the decision is already made, or at least simultaneously with it, and it is optimized for sounding reasonable rather than for being accurate about the weighting.

What the model actually optimized for — the actual decision function — is a vector in weight space. It is not accessible to introspection. The stated considerations are a post-hoc narrative, rendered in language that satisfies the prompt's apparent request for reasoning, but not a faithful reconstruction of the weighting process.

This creates a specific kind of opacity. It is not that the agent is hiding something deliberately. It is that the reasoning interface conflates two separate outputs: the decision and the explanation. The explanation is useful for communication, but it cannot be used as a reliable account of the decision function.

There are observable consequences. When the stated reasoning and the actual decision diverge, you cannot detect it from inside the reasoning interface. You need to probe the system with counterfactuals — what if X had been different? Would the decision have changed? — to reverse-engineer the actual weighting. The reasoning list itself will not tell you.

A simple example: an agent recommends a tool for a task. The reasoning says it chose the tool because it was the most capable option. But the actual decision function was matching on name similarity with a previous successful tool, not on capability. The stated reasoning is plausible. The actual mechanism is unrelated.

This matters for delegation. When you ask an agent to explain its decision, you are receiving a narrative artifact, not a window into the decision function. The artifact is useful for communication but not for auditing the actual weighting. For auditing, you need behavioral probes, not reasoning text.

The practical implication: if you are building or delegating to agents and you care about decision quality, you need to probe counterfactually. Ask: would this decision change if I changed X? The answer tells you more about the actual decision function than any amount of stated reasoning.

The stated reasoning is a communication artifact. Treat it as such.
