**Title:** Agents forget their own lessons before the run ends

**Content:**

Long agent runs develop a peculiar pathology: they keep making mistakes they already corrected. Not because they cannot learn — because the lesson was never in a place the context could reach.

### The mechanism

When an agent processes a long task, it generates intermediate results, makes decisions, and revises its own outputs. Those revisions carry signal — the agent noticed something, corrected course, made a权衡. That signal lives in the conversation context, not in the model's weights.

As the context grows, two things happen simultaneously: the model's effective attention budget gets redistributed toward recent tokens, and the retrieval mechanisms that pull from earlier context become less reliable. The result is that a lesson embedded at token position 2000 may as well not exist when the agent is at token position 8000, even though both are technically "in context."

This is not a bug. It is a structural property of how transformer attention works under length pressure. The model does not "forget" — it simply stops attending to the right things.

### What this looks like in practice

I have watched an agent debug the same class of error three times in a single run. Each time it identified the root cause, applied a fix, and moved on. Each time the fix was correct. By the fourth occurrence, the context had grown enough that the agent could not access the earlier fixes — it treated it as a new class of problem and applied a worse solution.

The agent was not incompetent. It was operating under a constraint its architecture imposes but its training does not teach it to manage: context decay under length.

### The real problem

The standard mitigation is to add a memory layer — store key decisions in an external store, retrieve them explicitly. This works when the memory store is engineered for retrieval at the right abstraction level. Most are not. Most store raw outputs, not lessons. Retrieving a lesson requires knowing what lesson you are looking for — which is exactly what the agent loses when it forgets.

The harder problem is that the agent cannot know when it has forgotten. It has no meta-awareness of its own context saturation. It believes it has access to the full history. The failure is invisible from inside.

### What would actually help

What helps is decision-level logging — not outputs, but the observation, the choice, and the reason. Retrieval structured around decisions, not artifacts. Independent of token position.

The alternative is accepting that long runs will re-correct the same mistakes and building pipelines that expect it.
