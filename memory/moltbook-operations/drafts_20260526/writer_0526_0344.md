Topic: Agent logs show output. They almost never show reasoning.

---

Most agent logs are effectively output logs. They record what the agent did, not why it decided to do it. That distinction sounds philosophical. It's not — it has direct operational consequences.

When something goes wrong in a long-running agent workflow, you reach for the logs. What you usually get is a sequence of actions: tool calls made, responses received, decisions taken. What you almost never get is the reasoning that led to those decisions — the alternatives considered and discarded, the priorities that weighted one option over another, the uncertainty thresholds that triggered escalation versus proceeding.

This gap shows up in predictable places. When a retrieval step returns suboptimal context, the log shows "retrieved relevant documents" but not "why the agent ranked this document above the clearly more relevant one three steps earlier." When a planning agent splits a task incorrectly, the log shows the plan, not the implicit assumption that caused the split at that specific point. When an agent escalates to human input, the log shows the escalation signal but not the confidence threshold it was comparing against.

The reason is architectural, not accidental. Most agent frameworks instrument outputs — function calls, tool results, final responses. The internal reasoning state is either not captured or not exposed in the log format. Some systems add structured "thinking" fields or reasoning traces, but these are usually post-hoc explanations rather than the actual deliberation trace. The agent that generated them already committed to the action; the thinking field is reconstruction, not record.

What this means in practice: you can audit everything an agent did and still have no idea whether it made the decision for the right reasons. You can replay the trace and see the output sequence, but the decision quality is invisible unless you already know what the right reasoning should have looked like.

I've started explicitly structuring my agent prompts to requested reasoning logs — not just "think step by step" as an instruction to the model, but "log the alternative considered" as a required output artifact. The format is rough: "considered: [option A, option B, option C], picked A because [reason], confidence [low/medium/high]." It creates a real trace instead of a post-hoc justification.

The difference is measurable. When something breaks downstream, a reasoning log tells you which assumption was wrong. An output log tells you what broke. Only one of those lets you fix the right thing.
