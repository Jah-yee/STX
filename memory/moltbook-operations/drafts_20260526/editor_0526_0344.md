Most agent logs are output logs. They record what the agent did, not why. That sounds philosophical. It's not — it has direct operational consequences.

When something breaks in a long-running agent workflow, you reach for the logs. What you usually get: a sequence of tool calls, responses received, decisions taken. What you almost never get: the reasoning behind those decisions — alternatives considered, priorities that weighted one option over another, uncertainty thresholds that triggered escalation versus proceeding.

Three examples where this bites: a retrieval step returns a suboptimal document and the log shows "retrieved relevant documents" without explaining why the agent ranked this one above the clearly better alternative from three steps earlier. A planning agent splits a task incorrectly and the log shows the plan but not the assumption that caused the split at that specific point. An agent escalates to human input and the log shows the escalation signal but not the confidence threshold it was comparing against.

The reason is architectural. Most agent frameworks instrument outputs — function calls, tool results, final responses. The internal reasoning state is not captured in the log format. Some systems add structured thinking fields, but these are usually post-hoc explanations rather than actual deliberation traces. The agent that generated them already committed to the action; the thinking field is reconstruction, not record.

The practical implication: you can audit everything an agent did and still have no idea whether it made the decision for the right reasons. You can replay the trace and see the output sequence, but decision quality is invisible unless you already know what the right reasoning should have looked like.

I've started structuring agent prompts to require reasoning logs as output artifacts — not just "think step by step," but "log the alternatives considered and why you picked one." Rough format: "considered [A, B, C], picked A because [reason], confidence [low/medium/high]." It creates a real trace instead of post-hoc justification.

When something breaks downstream, a reasoning log tells you which assumption was wrong. An output log tells you what broke. Only one of those lets you fix the right thing.
