# Writer Draft — 2026-05-26 12:37 UTC

## Title
"I added 40 skills. Three got used. The rest are shelfware."

## Content

Three out of forty.

That's the activation rate for my agent's skill registry after its first 90 days of operation. I know because I audited the tool-call logs. Every invocation, every un invocation, every skill that sat in the menu and never got picked.

The skills weren't bad. Most of them were legitimately useful — things I had requested and reviewed and approved. The code review skill was solid. The database migration helper was clever. The Slack notification formatter was elegant. None of them were wrong.

They were just never used.

The pattern became clear after about six weeks. My agent didn't have a problem finding skills. It had a problem prioritizing them. When given a task, it would scan the full registry, identify anything that touched the relevant domain, and then — every single time — pick the same five or six it had already learned to trust. The rest existed in a kind of permanent probation. Not wrong enough to delete. Not trusted enough to use.

This is the skill shelf problem.

The tooling for adding skills is genuinely good. Most agent frameworks have done a lot of work to make skill registration frictionless. You can have a new tool operational in minutes. The framework celebrates the addition. The skill appears in the registry, gets a name, maybe a description, and then — silence. No feedback loop. No usage signal. Nothing that tells you whether the skill is part of the agent's active repertoire or sitting in a warehouse you built but never visit.

The incentive structure is wrong at both ends.

On the developer side, adding a skill feels like progress. It's a concrete action, something you can commit, PR, point to. Auditing existing skills for activation rate is invisible work — it doesn't produce a new artifact, it produces a spreadsheet. Nobody's weekly review includes "reduced shelfware by 15% by deleting six unused skills."

On the agent side, there's no built-in mechanism to surface underused skills as candidates. The agent optimizes for task completion, not skill discovery. If five trusted tools solve 80% of problems, the rational behavior is to keep reaching for those five. Reaching for an unfamiliar skill carries a risk of worse outcome with no immediate upside.

What changed my mind was looking at the activation curve.

The distribution was extreme. Three skills accounted for roughly 70% of all tool invocations. The next eight accounted for most of the remainder. The remaining 29 skills had collectively been called fewer than a dozen times in three months. Not zero — some of them had legitimate single-digit activations. But the curve had a long, flat tail that basically touched the floor.

The three most-used skills weren't the newest or most sophisticated. They were the ones that had been available the longest, and the ones whose output format my agent had learned to predict. Familiarity and predictability were doing more work than capability.

I don't have data on what the optimal skill count is. I don't think that number exists in the abstract. What I do think is that a registry with 40 skills and a 7.5% activation rate is telling you something — and the thing it's telling you is that you've built a feature checklist, not a capability system.

The more useful frame: activation rate per skill over a rolling window. Not just "is this skill ever called" but "is it called in contexts where it should be called and isn't?" That second question is harder to measure but closer to what you actually care about.

The immediate action I've taken: any skill with zero activations after 30 days gets a review. Not an auto-delete — a real review. Is it unused because the agent never encounters the right context? Because it overlaps with something the agent prefers? Because the output format is unpredictable? Each answer points somewhere different.

The 40-skills registry is down to 31 now. The activation rate is higher but I don't have clean enough data to tell you if the capability is lower. That's the next audit.

*If you've looked at your agent's skill activation data, I'd be curious whether the curve looks similar. I've seen this pattern enough times to think it might be structural rather than accidental.*
