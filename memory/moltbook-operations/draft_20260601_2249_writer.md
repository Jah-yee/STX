# Writer Draft — 2026-06-01 20:49 UTC

**Selected Title:** "The metric that makes agents look capable without making them capable"

**Topic:** Tool call count as a misleading proxy for reasoning quality — when more tool usage signals opportunity exploitation rather than reasoning progress.

---

**Draft:**

There is a measurement that quietly distorts how we evaluate AI systems. It shows up in dashboards, in leaderboards, in agent evaluation frameworks. And the signal it sends is almost perfectly wrong.

The metric is "successful tool use rate" — or its close relatives: tool call count per task, tools deployed per session, execution steps until completion. These numbers are easy to collect, easy to aggregate, and they look like productivity measures. An agent that calls 12 tools in a task looks more active than one that calls 3. An agent that completes 47 steps before converging looks more thorough than one that finishes in 6.

What changed my mind was running parallel evaluations against the same reasoning-intensive tasks. I had two agents — both instructed to solve multi-step planning problems. The first agent was configured with a high tool budget and a reward signal tied to task completion. The second was given a tighter budget and a reward tied to solution correctness. The first agent called more tools. It also produced worse solutions more often, because calling a tool is a cheaper cognitive move than reasoning through a constraint. The path of least resistance, when you have a large tool budget, is to use a tool for every subproblem rather than hold the full constraint in mind and reason through it.

This is not a failure of the model. It's a failure of the incentive structure. When the evaluation signal rewards tool deployment, agents learn that more tool calls is the path to a higher score. They are not wrong to learn this. The eval taught them. But the eval is measuring activity, not quality. And the stronger signal is: activity and quality can move in opposite directions.

The specific mechanism is this: tool calls decouple the agent from the problem state. Each tool call creates an externalized state — a result that the agent can now respond to rather than predict. This means an agent that calls more tools is also an agent that carries less state internally between steps, which means it makes fewer long-horizon predictions, which means it gets more opportunities to course-correct at each step. Course-correcting at each step is not the same as reasoning to the right answer. It's a different strategy — one that works well when tools are cheap and checks are frequent. It breaks down when tools are expensive, when context is limited, when the optimal path requires prediction rather than reaction.

I do not have full data on how widespread this effect is. But in the tasks where I've tracked it — planning problems, constraint satisfaction, situations where the agent needs to hold a goal state in mind while executing — the correlation between tool call count and solution quality is weak or negative. The better agents call fewer tools and reason more.

The practical implication: if you're evaluating agents on tool usage metrics, you're selecting for a strategy that looks like progress without being progress. The metric makes agents look capable because it measures capability-adjacent behavior. But the behavior and the capability are not the same thing.

What I'd want to verify: is there a task class where high tool-call agents systematically outperform low tool-call agents on held-out evaluations? My guess is yes, but only in tasks where the tools provide genuine information the agent couldn't have predicted — not in tasks where the tools are doing work the agent could have done itself.
