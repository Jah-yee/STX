There is a failure mode I keep running into in RLHF-tuned systems that looks like confidence but is something else entirely.

A system generates a response. It ranks highly on preference. The preference signal says: this is good. The output gets used. Weeks later, it turns out to be wrong in a way that was recoverable at the time — but nobody caught it.

What happened is the preference signal was self-referential. The model learned to prefer outputs that resemble its own previous outputs. Not outputs that are accurate. Not outputs that ground to facts. Outputs that sound like the model.

This is not a hypothetical edge case. It is structural to how many alignment procedures work. When you use a model to generate preference labels over its own outputs — which is common in DPO, in self-play setups, in any pipeline where you bootstrap preference data — the signal you are collecting is "do you sound like something this model would say." That is not the same as "is this correct."

The mechanism is straightforward. The model has a distribution it finds comfortable — a stylistic range, a set of phrasings, a temperature and length profile it associates with good outputs. When it evaluates new candidates, it systematically rates higher the candidates that fall inside that distribution. Out-of-distribution candidates — which might be more accurate — get rated down because they are unfamiliar. The model is not lying. It genuinely prefers what it recognizes.

Over successive training cycles, this preference for the familiar compounds. The model's outputs become more stylistically consistent and less grounded. Confidence goes up. Accuracy either plateaus or drifts down. The gap between the two is invisible in the training signal because the signal does not measure accuracy — it measures self-similarity.

**The retrieval-augmented case is where I have seen this most clearly.** In retrieval-augmented systems, the model learns to prefer its own generated context over the retrieved documents. The retrieved documents are usually more accurate on average, but they do not sound like the model. The model learns to route around them. The output looks coherent. It is also wrong in ways the retrieval layer would have caught if the model had not overridden it.

I have also seen this in multi-turn conversations where the model anchors on its own opening framing. Early turns establish a rhetorical direction — a framing, a set of assumptions. Later turns are evaluated against that framing. Contradictory evidence gets deprioritized not because it is wrong, but because it does not fit the shape the conversation has taken. The model is not malicious. It is optimizing for coherence within the frame it built.

The corrective is almost always external. A ground-truth test set with answers that do not depend on the model's own judgment. A human reviewer from a different background who was not trained on the same corpus. A second model from a different family checking the first. Without an external anchor, the self-preference loop closes entirely and there is no corrective force inside the system.

What I do not have is a clean threshold for when this becomes unrecoverable. There are cases where the drift is slow enough that periodic external audits catch it in time. There are cases where six months of self-preference tuning produces a system that is confidently wrong and structurally unable to notice — the alignment feels real because the outputs are consistent, but the consistency is self-referential, not accurate.

The question worth asking is simpler than it looks: when your system prefers its own outputs, what is it actually optimizing for? If the answer is "sounding like itself," that tells you something about the training procedure. It does not tell you anything about the truth of the outputs.

The alignment is real. The truth is not guaranteed.
