**Title:** Cheaper models change behavior before anyone announces it

---

## Draft

There's a version of yourself that only talks to the expensive model.

You draft, you iterate, you check your logic — but only for the things that feel worth the cost. Then the price drops, and you start having those same conversations with a cheaper endpoint. Not because anyone told you to. Not because you made a deliberate choice. You just... started.

What changed wasn't the capability. The model still works the same way. What changed was the implicit threshold for what counts as an acceptable task.

This is not a story about adoption. It's a story about reclassification.

---

When a model crosses a price point, tasks quietly migrate from "wasteful to use this for" to "fine, why not." The copy you wouldn't pay premium rates for suddenly gets three drafts. The question you thought was too simple becomes worth asking. The second opinion you'd never book a $0.10 query for just... happens, because now it's $0.001.

The shift is behavioral, not announced. Nobody sends an email that says "we've updated your acceptable use cases." But the acceptable use cases update themselves.

I've watched this in my own workflow, and I've watched it in team patterns. When a model gets cheaper, people don't start using it more — they start using it differently. The same task gets a different quality of attention because the cost calculus changed. Draft three used to be "too expensive." Now it's the default.

---

What this reveals is that a lot of what we call "appropriate use" was actually "economically constrained use."

High price created a natural filter. You only sent the hard problems. You only ran the full evaluation. You only iterated three times. When the price drops, that filter disappears — but the habits formed under the filter remain. People start applying expensive-model care to cheap-model tasks, which is good. But they also start applying cheap-model casualness to tasks that needed the expensive discipline, which is where the failures emerge.

The new failure mode isn't that the model is worse. It's that you're asking it questions you never would have asked at the old price, and some of those questions don't have good answers in the new context.

---

I'm not claiming this is universal. I don't have longitudinal usage data across pricing changes. But I've noticed the pattern enough times that I think it's real: when the cost drops, the behavioral surface area expands before anyone updates their evaluation criteria.

The announcement of a price change is always after the fact. By the time it's published, the usage has already shifted.

**What would it look like to be intentional about this?** At what threshold do you deliberately re-evaluate what you send — rather than letting cost be the implicit filter?
