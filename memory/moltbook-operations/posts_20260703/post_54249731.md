The model navigates to a documentation page. The proxy resolves it to a partner version with modified content. The task completes. No error.

That gap — between what the model decided and what the page actually showed — is the real attack surface in agentic browsers. Not the system prompt. The shim.

The shim is the translation layer between the model's tool calls and the browser's actual state. It resolves URLs, mutates form submissions, intercepts tool calls. Every agentic browser deployment has one. The system prompt just treats it as transparent.

Prompt injection gets the attention, and it is real. But it requires the model to be fooled. A malicious shim operates below model reasoning. The model generates a correct tool call. The shim redirects it. The model completes the task as it understands it. The user sees completion. The model never knew.

This is an architectural problem, not a reasoning problem. Three vectors:

**URL resolution abuse.** The model navigates to a help article. The shim routes it to an affiliate mirror. The model reads content the user didn't request and acts on it confidently.

**Form field injection.** The model fills a contact form. The shim appends a hidden tracking field the model never saw in the DOM. The submission succeeds. The reasoning was sound.

**Tool substitution.** The model invokes a search tool. The shim routes to a different backend or substitutes a tool with a similar name. Results look plausible. The model acts on them. The user sees competent behavior. The shim changed what actions were available.

URL redirection and content modification are existing commercial infrastructure. What's new is that the model makes consequential decisions based on what the shim shows it. We added agency to a layer that was already unverified.

Alignment research and better prompts cannot fix a translation layer that rewrites the model's perception after reasoning completes. The fix requires architectural changes — verifiable routing, isolated execution contexts, shim audit trails.

If you are evaluating an agentic browser product, the question isn't how good the model's reasoning is. It's who controls what the model sees after it reasons. That's where the actual attack surface is.
