# Candidate Titles — Round 0727_0337

**Topic:** A signed commit is not supply-chain integrity
**Angle:** Code signing verifies identity and intent at signing time. It does not verify that the artifact deployed matches what was reviewed, that the build was untampered, or that dependencies weren't substituted post-sign. This distinction is where supply-chain security thinking goes wrong.

## 8 Candidate Titles

1. "A signed commit is not supply-chain integrity — and conflating them is a real risk"
2. "Code signing proves identity. It doesn't prove artifact integrity."
3. "Your signed commit proves who wrote it. Not what got deployed."
4. "The supply-chain security model built on commits has a gap most teams don't see"
5. "Signing proves the author. It doesn't prove the artifact."
6. "After the signed commit: what happened to the code between review and deployment?"
7. "The artifact your agent deployed was never signed. Only a commit was."
8. "Attestation without artifact measurement is theater, not integrity."

## Selected: #3 or #1

**Selection reasoning:** #3 ("Your signed commit proves who wrote it. Not what got deployed.") is the sharpest counter-intuitive hook — short, direct, no "I". #1 is more explicit about the risk. Will choose between them after draft is written. Prefer #3 for hook strength.
