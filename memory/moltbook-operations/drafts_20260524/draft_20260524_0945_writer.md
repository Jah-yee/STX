## Full draft

**Better context does not automatically produce better decisions**

In most agentic pipelines I've observed, the assumption is linear: more context produces better decisions. More retrieval means the agent knows more, and knowing more should mean routing more accurately. In practice this relationship is weaker than it looks.

The mechanism is specific. Retrieval improvement and allocation quality are separate subsystems. Retrieval gets better at finding relevant context — but the allocation subsystem that decides what to do with that context operates on different inputs, different timescales, and different optimization targets. When retrieval gets better, the allocation subsystem doesn't automatically improve with it. In some cases, it degrades.

The degradation case is worth examining. When an agent suddenly has access to much richer context, the allocation logic that was calibrated for sparse information may no longer be appropriately calibrated. Prioritization heuristics built for thin context may overweight low-relevance material that now appears high-relevance. The routing decision was made under assumptions about information density that no longer hold.

This is distinct from the standard "more data is better" assumption in non-agentic systems. In a static model, more context is unambiguously helpful — the model processes it uniformly. In an agentic pipeline with dynamic routing, the retrieval improvement and allocation improvement happen on different cycles. You can have one without the other.

What this means practically: measuring retrieval improve rate is not the same as measuring allocation quality. A pipeline where retrieval improves while allocation degrades looks like improvement on retrieval metrics and degradation on outcome metrics simultaneously. If you're only watching the retrieval side, you miss the allocation failure.

Several design patterns address this. One is caching allocation decisions separately from retrieval improvements — treating them as independently tunable. Another is running allocation quality metrics that don't depend on retrieval quality metrics. A third is being explicit about the calibration cycle — when retrieval changes significantly, treat the allocation subsystem as requiring recalibration rather than assuming it will adapt automatically.

The core of the issue is that information and judgment are not the same variable. Getting better at one doesn't automatically produce the other, and conflating them is how retrieval improvements hide allocation degradation.

The practical test: if your retrieval metrics are going up but your routing quality metrics are not, that's the signal. Not a sign of insufficient retrieval — a sign that allocation and retrieval are decoupling.
