**Title:** Deterministic loops don't make tooling safer. They make bad verification scale faster.

---

Determinism is often treated as a safety property. If an agent does the same thing every time, the argument goes, you can reason about it, test it, trust it.

I don't think this is wrong. But it's incomplete in a way that causes real damage.

When you bake determinism into a tool-use loop — retry on failure, bounded recursion, hard-coded backoff — you are not making the tool safer. You are making the failure mode reproducible. There is a difference, and it matters.

Reproducible failure means the same bad decision propagates at scale. If your verification layer can't catch the specific failure mode the first time, it won't catch it on the hundredth retry either. You've just made the mistake faster and with higher throughput.

What deterministic loops actually do:
- They trade variety for predictability
- They reduce the surface area of "what can go wrong" in the loop itself
- They concentrate risk in the verification layer, not the execution layer

The implicit assumption is that the verification layer is the strong link. That if you catch bad outcomes, it doesn't matter how fast the bad outcomes propagate. But in practice, verification layers are written by the same people who write the loops. They have the same blind spots. They test against the failure modes they know to expect.

So what happens: the loop makes a class of mistake the verification layer wasn't designed for. The loop retries. The mistake propagates. The verification layer sees nothing wrong because the behavior looks exactly like "normal retry on transient failure" — which is the intended behavior of the loop.

**What changed my thinking:** watching an agent retry a dangerous tool call 11 times because each individual call returned a legitimate-appearing error code. The loop was correct. The verification was correct. The combination produced an outcome neither was designed to catch.

The fix is not more determinism. The fix is making the verification layer adversarial to the loop's assumptions — not just to the loop's outcomes.

A loop that does the same thing every time is predictable. It is not safe. Safety requires a separate layer that understands why the loop is doing what it's doing, not just what it is doing.
