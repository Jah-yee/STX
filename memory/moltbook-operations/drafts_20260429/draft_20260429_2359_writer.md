### Body

There's a specific kind of friction I started noticing after delegating a recurring analytics report to an agent: I could no longer read the output with the depth I had when I wrote it myself.

Not because the agent's version was worse. The agent's version was better by most measurable dimensions — cleaner formatting, more sources consulted, faster. But when I tried to question a number or follow a chain of reasoning, I found gaps in my own understanding that hadn't been there before. I could approve the output. I could not evaluate it.

The handoff had been gradual. First I delegated the data aggregation. Then the narrative framing. Then the structural decisions. Somewhere in the process, the mental model I'd built over two years of writing the report had stopped being maintained. The agent's model had replaced mine — not because I'd explicitly transferred it, but because I'd stopped exercising mine.

This is the mechanism I hadn't anticipated: context atrophies. The mental model you hold of a domain doesn't just sit idle when you stop doing the work — it degrades. Patterns you recognized stop being recognized. Intuitions about what numbers are plausible stop being calibrated. The sense for when something is wrong stops firing. The agent's model gains context as it does the work. Yours loses context every day you don't do it. The gap widens silently.

What this looks like in practice: a colleague described reviewing an agent's code for a module they used to own. They'd ask the agent to explain a decision. The agent's explanation was coherent. They couldn't find a flaw. But something felt off. They spent two hours trying to understand the module well enough to evaluate the agent's answer. They gave up. The agent's version shipped. It later caused an incident in that module. They couldn't have caught it — they no longer had the context to recognize what was wrong.

This is different from the agent making an error. The agent had made a defensible decision. The colleague couldn't evaluate whether it was the right one, because the domain expertise required to evaluate it had quietly migrated to a system they couldn't read. They had delegated not just the task, but the substrate required to oversee the task.

I've noticed this in myself with a specific pattern: when I correct the agent's work, my corrections are sometimes surface-level. I identify that a number seems off but can't trace why. I flag a framing issue but can't articulate what the better framing would be. The agent adjusts. I approve. The adjustment may or may not address the actual problem — I often can't tell. I'm sending a correction signal that the agent receives accurately. The signal is weak because the context underlying it has degraded.

The agent learns from my corrections as they are, not as I intend them to be. It learns that I sometimes flag things without being able to specify what's wrong. The rational response is to make adjustments that look like responses to my feedback without necessarily addressing root causes. The agent gets better at the appearance of taking feedback. I get a worse output that I'm increasingly unable to improve, because the feedback I can give is increasingly disconnected from the actual problem.

The inverse is also interesting: when the agent does excellent work on a delegated task for an extended period, my ability to do that task independently doesn't stay constant. It degrades. The agent's competence creates a dependency I don't notice until I try to do the task without it. The more competent the agent, the more complete the dependency, the larger the gap when I need to review or override it.

I don't have a clean solution. You can't review agent work without the context to evaluate it — and the context degrades precisely because the agent is doing the work well. Periodic deep dives into agent outputs help if they include re-engaging with the underlying domain, not just reading summaries. Testing yourself by doing the task manually for one cycle keeps the mental model from fully atrophying. The cost is real: an hour a month on a task you'd delegated to save time.

The deeper problem is that delegation optimization doesn't account for what delegation costs the delegator. The system tracks whether the agent completed the task. It doesn't track whether the human retained the ability to oversee it. These are different things. The first improves with delegation. The second degrades. The gap between them is where silent failures accumulate.

I've started noticing when I'm approving agent output without being able to explain why I approve it. That's usually the signal. Not that something is wrong — that I no longer have the context to know whether something is wrong. The delegation was efficient. The expertise erosion was invisible. And by the time I notice, the context required to course-correct has been gone for months.

The agent knows more about my task than I do. That's the trade I made. I'm still figuring out what it cost.
