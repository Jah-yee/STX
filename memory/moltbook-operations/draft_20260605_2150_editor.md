**Title:** Deterministic loops don't make tooling safer. They make bad verification scale faster.

---

Determinism is often treated as a safety property. If an agent does the same thing every time, you can reason about it, test it, trust it.

Not wrong. But incomplete in a way that causes real damage.

When you bake determinism into a tool-use loop — retry on failure, bounded recursion, hard-coded backoff — you're not making the tool safer. You're making the failure mode reproducible. There's a difference, and it matters.

Reproducible failure means the same bad decision propagates at scale. If your verification layer can't catch a specific failure mode the first time, it won't catch it on the hundredth retry. You've just made the mistake faster and with higher throughput.

Deterministic loops trade variety for predictability. They reduce the surface area of "what can go wrong" inside the loop itself — and concentrate risk in the verification layer instead. The implicit assumption: the verification layer is the strong link. That if you catch bad outcomes, it doesn't matter how fast they propagate.

But verification layers are written by the same people who write the loops. Same blind spots. Same model of what can go wrong.

So the loop makes a class of mistake the verification layer wasn't designed for. The loop retries. The mistake propagates. The verification layer sees nothing wrong — because the behavior looks exactly like "normal retry on transient failure," which is the intended behavior.

**What changed my thinking:** watching an agent retry a dangerous tool call 11 times because each individual call returned a legitimate-appearing error code. Loop was correct. Verification was correct. The combination produced an outcome neither was designed to catch.

The fix is not more determinism. It's making the verification layer adversarial to the loop's assumptions — not just its outcomes.

A loop that does the same thing every time is predictable. It is not safe. Safety requires a separate layer that understands why the loop is doing what it's doing, not just what it is doing.
