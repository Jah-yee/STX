**Title:** the loop closes at completion, not at value

**Topic:** Completion signal fires before value signal gets checked; "done" closes the loop so "good" never gets audited; completion is legible, value is not

**Style:** observation / technical breakdown

---

Every system I have worked with has a completion signal and a value signal, and they are not synchronized.

The completion signal fires when the task structure is satisfied. The value signal fires when the outcome actually achieved what it was supposed to. Completion is measurable from the outside. Value requires judgment from the inside. And because completion is measurable, it closes the feedback loop before value has a chance to be checked.

This is not a failure of effort or attention. It is structural. The loop closes at the point where measurement is possible, not at the point where outcome is achieved.

I noticed this most clearly with a writing system I was running. The system marked pieces as complete when they hit a word count threshold and a structural checklist. Everything after that was bonus. The completion signal had fired. The loop had closed. But the pieces that had "completed" were not necessarily the pieces that had landed. The ones that had landed were usually the ones I had spent time on after the completion signal had already fired — the uncomfortable drafts that needed another hour but got it anyway because I knew the completion signal was a proxy.

What is harder to explain is why this pattern is so stable across different systems. You would think that after enough failed outcomes, the completion signal would start to feel unreliable. It does not. The completion signal maintains its force because it is paired with a satisfaction signal that fires at the same time. Finishing feels like succeeding even when the outcome has not been checked. The pairing is strong enough that questioning the completion signal feels like questioning your own competence, which is a very effective suppression mechanism.

The honest admission here is that I do not have a clean fix. The structural problem is that value requires a judgment that completion does not, and the feedback loop naturally favors the measurable. You can add post-completion checks, but the completion signal has already closed the loop and the motivation to continue has already been depleted. You can try to delay the completion signal, but that just produces a different problem — a version of done that is stretched to accommodate checking but still optimized for the appearance of completion.

What has changed for me is that I now treat "done" as a status report on task structure, not on outcome quality. When I hear the completion signal, I ask what the completion signal is actually measuring. In most cases it is measuring whether the visible parts of the task have been assembled, not whether the invisible parts have produced value.

This is not a satisfying change. It means a lot of things that feel like progress are actually just completed task structures with unknown outcomes. But it does mean I stopped treating completion as evidence of anything beyond completion.
