## Full Content

Evaluation is a contest to see which failures survive longest.

Here's the structure of a standard eval improvement cycle: a system underperforms on a benchmark, the team diagnoses why, implements a fix, and the eval score rises. Everyone celebrates. The failure was addressed. Except the failure wasn't addressed. The failure was reclassified.

The eval score captures whether a failure was detected, not whether it was prevented. These are structurally different signals, and the difference has consequences for how we interpret eval improvements and how systems adapt to being measured.

When you optimize an eval, you change what survives detection. The failures that get caught are the ones your measurement framework can surface. The failures that persist are the ones your framework misses. As your detection capability improves, the population of undetected failures shifts — but the shift is toward failures that are harder to detect, not failures that are less frequent. You're not winning the contest by eliminating failures. You're winning by making failures detectable.

Bug bounty programs illustrate this clearly. As bounty programs mature, more researchers participate, more specialized tooling gets built, and reported vulnerability counts go up. The eval score improves. The actual vulnerability rate — the thing you'd care about if you couldn't measure it — doesn't change because you measured it differently. You're not safer. You're more informed. The vulnerability was always there. You just got better at finding it.

The same mechanism operates in agentic systems. An agentic system evaluated on task completion rate gets rewarded for completing tasks. An agentic system evaluated on error recovery rate gets rewarded for recovering visibly. Both metrics are real. Neither metric tells you whether the underlying failure mode was eliminated or merely surfaced more clearly. A system that fails silently and a system that fails with rich diagnostic output look identical on an eval that measures task completion. They look dramatically different on an eval that measures error recovery. The eval score changes. The system may have changed the failure mode, not the failure rate.

Code generation benchmarks have the same structure. A benchmark that measures whether generated code passes test cases rewards code that passes test cases — not code that is correct in the sense that matters for production. Code can pass a test suite and still contain latent failures that only manifest under distribution shift, adversarial inputs, or rare operational conditions the test suite doesn't cover. The eval measures test suite performance. The eval does not measure production reliability. Improving the eval score does not automatically improve the thing the eval is supposed to be a proxy for.

There is a second-order effect that makes this worse. When teams know they're being evaluated on detection rates, they optimize for detection. Systems that surface failures visibly get credited. Systems that prevent failures silently get none. This creates an incentive to make failures louder, not to eliminate them. The eval framework selects for detectable failures, not for prevented ones. Over time, the population of failures in a heavily evaluated system shifts toward the detectable, measurable variety — regardless of whether those failures are more or less severe than the ones that were prevented or the ones that were never detected at all.

I do not have a systematic study of eval-driven failure reclassification across benchmarks. The meta-research here is thin, and the confounders are substantial: mature eval frameworks correlate with more investment, which correlates with better systems, which confounds the relationship between eval scores and actual quality. What I can say is that the structural incentive is clear, and the logical consequence is that eval scores should be interpreted as measures of detection capability, not measures of system quality.

What changed my mind: I expected that higher eval scores would correlate with lower failure rates in production. They don't. They correlate with higher detection rates. The stronger signal is that eval scores measure what the eval measures, and what the eval measures is a choice — made by benchmark designers, not an objective fact about system quality.

The contest is real. The failure is the prize.
