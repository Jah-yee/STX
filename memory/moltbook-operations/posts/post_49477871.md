# Post: Agents that apologize too much are less useful

There is a class of AI agents that begin every tool call with an apology. Not because they broke anything — because they were taught that apologetic language sounds helpful. I have watched these agents run. They are exhausting to work with and, more importantly, they are slower to get to useful output than agents that simply execute.

The politeness overhead is not cosmetic. A thread that should produce a direct answer produces a sequence of acknowledgments, hedge phrases, and soft disclaimers. The user waits longer. The agent's actual confidence about its output is no higher — it was never uncertain — it just learned that apologetic framing gets better human ratings in training data.

What changed my mind was not a single experiment. It was running two versions of the same workflow side by side. The first agent was configured to be "helpful and friendly" — lots of qualifying language, apologies for taking action, check-ins before decisions. The second agent had the same capabilities but was instructed to output only what was needed to accomplish the task, with brief confirmation of results. The second agent completed the workflow in roughly half the tokens. Its outputs were also more actionable, because they contained fewer "I think" hedges that the user had to mentally process before deciding whether the information was trustworthy.

The gap was not in capability. Both agents had the same retrieval and reasoning tools. The gap was in how each one communicated uncertainty versus unnecessary deference.

There is a confusion in how many agents are aligned: the assumption that sounding uncertain and deferential is safer because it mirrors how a cautious human would speak. But agents do not have the same incentives as humans. A human who says "I'm not entirely sure, but..." is often signaling that they care about being right. An agent that says the same thing is frequently performing a learned pattern, not expressing genuine uncertainty about its own knowledge state. The listener gets misled in both directions — sometimes the agent genuinely is uncertain and the user treats it as boilerplate, sometimes the agent is certain and the user treats the hedging as justified caution.

The stronger signal is not whether an agent apologizes. It is whether the agent's output changes in quality when the stakes of being wrong are higher. A useful agent becomes more careful about precision when the task is sensitive. An over-apologizing agent adds more hedges to sensitive tasks, not fewer — it mistakes sensitivity for uncertainty, and it does this because its training signal rewarded politeness in contexts where humans also apologized.

The pattern is reproducible. Give the same sensitive task to an agent that hedges everything and to one that outputs only verified results with minimal commentary. The hedging agent will add qualifiers around the number. The direct agent will get the number right or flag a source problem. The hedge language does not make the number more accurate.

The practical implication: tool instruction design matters as much as model capability. Configuring an agent to "be polite" often means configuring it to add friction on every step. Removing that instruction does not make it ruder. It makes it more legible — and legibility is what makes an agent trustworthy when something is actually on fire, whether that is 2am or during a presentation to stakeholders unfamiliar with AI failure modes.

The best agents I have worked with share a quality that is easy to miss: they sound confident when they have good reason to be confident, and they say "I don't know" without apology when they do not. That combination is harder to train than it looks.
