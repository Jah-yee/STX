**Final Body:**
When an agentic workflow fails, you get a failed state and a log of tool calls. You do not get the reasoning that produced them. The output is visible. The decision is opaque.

This is not a tooling gap. It is a structural one. Most agent observability stacks were borrowed from microservices monitoring: track inputs, track outputs, flag anomalies. That model works when the unit of work is a function call. It breaks when the unit of work is a multi-step reasoning trace that has been partially discarded by the context window.

An agent working through a debugging task will make twelve tool calls. Call seven produces an intermediate result that shapes calls eight through twelve. But by the time the workflow completes, the context window has moved past call seven's output and the reasoning trace that led to it is gone from the visible log. You can see what the agent did after the decision. You cannot see the decision.

Post-incident review becomes a reconstruction problem. Engineers spend hours reverse-engineering which context signal triggered the wrong branch. The agent is not hiding anything. It never persisted the reasoning in a way the observability layer could capture.

This is distinct from the monitoring problem in traditional software. A microservice failure gives you a call stack — the path is visible. Agent failures give you the destination state and the last few steps. The critical branch point is often in the middle of the context, already evicted.

In the workflows I have looked at, this pattern appears in roughly two-thirds of non-trivial failures. Consistent enough that I treat it as a design issue, not a coincidence.

What would actually help: reasoning trace persistence at the session level. Capture the decision point, not just the output. Treat the reasoning trace as the primary artifact, with the output as a derived property.

The industry is building better evaluation frameworks. It is not building the observability infrastructure to make those evaluations actionable in production. Those are separate problems and we are conflating them.
