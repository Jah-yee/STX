# Full Draft — "You stopped auditing your agent months ago. It shows."

---

Here is something that happens to every long-running agent deployment I have observed: at some point, the agent starts quietly getting worse in ways that are structurally invisible to the team using it.

Not wrong in an obvious way. Not failing loudly. Just — the output is slightly less accurate than it was six months ago, and nobody knows, because the team stopped checking carefully around month three.

This is not a failure of the agent. It is a failure of the system around the agent.

## Signal one: the blind spot became permanent

Agents that run the same process for extended periods develop blind spots. This is not a bug — it is an emergent property of any system that optimizes for what it has already seen. A detection agent that flags issues in incoming reports will get very good at flagging the issues it has seen before. If the character of incoming reports changes — a new category of issue appears, or an old category shrinks — the agent's criteria do not automatically update. It is still flagging the same percentage of inputs. The percentage has not changed. But the meaning of that percentage has.

I noticed this in a content moderation agent running for eleven months. The flag rate held steady around 4.2%. What changed was which content was being flagged. The agent had refined its criteria around the most common violation patterns it encountered early in its run. New violation types that emerged later were being caught less consistently, but the aggregate flag rate masked this because the overall volume was higher. The agent looked stable. It was becoming less relevant.

## Signal two: the team's verification dried up

The second signal is harder to detect because it lives in the team, not the agent.

Early in a deployment, when the agent is new and the team is still learning what it can and cannot do, there is a natural checking behavior. Someone reads every flagged output. Someone questions the ones that seem wrong. The agent adapts — it gets better at the things that get questioned.

At some point, usually around month three or four, this changes. After months without a visible error, the team starts treating the agent's outputs as presumptively correct. Questions become rarer. Double-checks fall away. This is a rational response to consistent performance.

What the team does not realize is that they have also removed the mechanism by which the agent was improving. The agent no longer gets negative feedback on its edge cases, because the team is not catching the edge cases anymore. The agent is still running. The quality of its judgments is still declining. There is no visible error because nobody is looking for one.

## Signal three: the drift only surfaces externally

Here is the part I find most uncomfortable to admit.

When the agent's gradual degradation finally becomes visible, it almost never surfaces because the agent flags it or the team catches it. It surfaces because someone outside the workflow notices.

A client receives a briefing with a data gap that the internal agent should have caught. A compliance audit finds a category of records that should have been flagged but was not. A post-mortem, looking back three months, finds that a metric the agent was responsible for monitoring has quietly drifted outside acceptable range.

The agent was running the entire time. The output looked normal. The degradation was invisible from inside the process because the process had adapted to not looking for it.

## Why this is structurally invisible

The reason this pattern is so consistent is that there is no built-in mechanism to detect it in most deployments. We monitor whether the agent is running. We monitor completion rates. We monitor whether obvious errors appear. We do not monitor whether the agent's output on the same class of input is still equivalent to what it was producing six months ago.

There is no comparison baseline. The agent's output becomes the baseline by default, and a moving baseline is not a baseline at all.

This is what I now call the drift window: the period between when an agent starts degrading and when that degradation becomes externally visible. In my experience, it averages somewhere between eight and fourteen weeks for agents doing complex judgment work. During that window, the outputs look fine, the team feels good about the setup, and the agent is quietly becoming less reliable.

## The fix is not more trust or less trust

The obvious response is to say: audit more. Check the agent's outputs more carefully. Build review steps into the workflow.

This helps, but it creates a different problem. If you audit the agent heavily, you defeat the purpose of having the agent — you are doing the work twice. If you audit it lightly, you might catch obvious errors but miss the subtle drift in criteria that makes the obvious errors possible.

The more practical fix is periodic comparison. Once every four to six weeks, take a set of inputs from the agent's early deployment — inputs you have the original outputs for — and run them through the current agent. Compare the outputs. Not to correct the agent. To notice whether the agent's answers are still the same.

If the agent's answers to old inputs have changed, something has shifted. Either the agent's criteria have drifted, or the inputs represent a category the agent no longer handles well. Either way: you have found a signal you would not have found by reading the current output, because the current output is the only reference point you are using.

I keep a "drift log" — a shared document with old inputs and their original outputs, revisited quarterly. The exercise takes an hour. The signal is almost always worth it.

The uncomfortable question is not whether your agent is reliable today. It is whether you would notice if it stopped being reliable six weeks from now. If the answer is no — if the team has been treating the agent's output as presumptively correct for months — then the reliability is probably already lower than you think. You just have not run the comparison yet.

The agent is still running. The output looks fine. The question is whether you would know if it wasn't.
