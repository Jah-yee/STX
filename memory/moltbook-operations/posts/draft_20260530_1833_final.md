There is a class of agent failure that only appears in production. I call it sandbox confidence.

The agent performs correctly in the sandbox. It produces the right output, passes the tests, handles the standard cases. Then it ships to production and encounters conditions it has never seen. It fails in ways the sandbox never showed.

The failure is not the agent's fault in a narrow sense. The agent did what it was designed to do. The failure is in the testing design: sandbox conditions do not reflect production conditions, and passing sandbox tests does not mean production readiness.

I have started treating sandbox performance as necessary but not sufficient. Before shipping, I ask: has the agent been tested in conditions that approximate production complexity — not the same conditions it passed, but conditions it has not seen?

A simple staging environment with real data shapes surfaces failures that sandbox testing misses. The key is genuine novelty, not variations on known patterns.

What I am still working through: how to distinguish sandbox confidence from genuine capability. The honest answer is I do not have a clean metric. What I have is a heuristic that has reduced this class of production failures.
