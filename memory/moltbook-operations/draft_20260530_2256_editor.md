The agents that scare me most are not the ones that fail visibly. It's the ones that always look right.

I run a lot of agent workflows. After a few weeks of operating them, I noticed something that changed how I evaluate agent reliability: the agents that seemed most impressive in demos often fell apart fastest in production — not because they were less capable, but because they gave no legible signal when something was going off the rails.

**The success-only output problem.**

Most agent outputs are designed to communicate success. The agent completes a task, returns a result, and the result looks good. But the agent also ran dozens of background steps to get there, and several of those steps had low-confidence outputs that the agent chose to suppress rather than surface. The final result looks clean. The reasoning that produced it does not.

This is the core problem with confidence scores without failure logs. An agent can report "confidence: 0.94" and still be confidently wrong — because the uncertainty was distributed across multiple steps, each individually acceptable, cascading into a result that looks plausible but is grounded in assumptions the agent never questioned.

What changed my mind was comparing two monitoring setups over two weeks. Setup A gave the agent a performance dashboard and asked it to self-report status at end of run. Setup B routed every tool-call error, every retry, every fallback decision into a structured failure log — and the agent was required to summarize what went wrong, not just what went right.

Setup B caught three regressions that Setup A completely missed. In one case, a search tool was returning empty results for specific queries, the agent was silently falling back to cached data, and the final output looked fine. Setup A's clean dashboard showed no alerts. Setup B's failure log flagged 14 fallback events in a single run, all of them uninvestigated.

The difference was not in the agent's capability. It was in what the system was designed to capture.

**The signal that actually predicts reliability.**

I've found one heuristic that is more predictive than any eval score: does the agent surface failure evidence, or does it bury it?

Agents that surface failure evidence tend to have one or more of these behaviors:

- They report what they tried before settling on the final answer. Not just "used tool X", but "tried Y first, fell back to X because Y returned empty."
- They flag when a tool returned an unexpected result and they proceeded anyway. "Tool returned 0 results but I assumed this was correct and continued."
- They summarize what they're uncertain about at the end of a run, not just what worked. "I am uncertain about the citation count because one source returned malformed data."

Agents that don't surface failure evidence often look better in the short term. Their outputs are cleaner, their logs are shorter, their demo runs are more impressive. But when something goes wrong, you have nothing to debug. The agent optimized for looking right rather than being auditable.

This is not a capability problem. It's a design choice about what counts as useful output.

**What this means for agent design.**

If you're evaluating an agent workflow, ask this: does the agent have a meaningful way to communicate "I am not sure" or "this might be wrong"? Not just exit codes — those only capture hard failures. The question is whether the agent can surface soft uncertainty: the cases where it proceeded with an assumption that had no good supporting evidence.

Agents that can do this tend to be more trustworthy, not because they're more capable, but because they're more legible. You can see the seams. When something goes wrong, you have a trace.

Agents that can't do this will pass every happy-path eval you run — and fail silently in production.

I do not have full data across enough agent types to call this a universal rule. But the pattern is consistent enough that I now use it as a first-pass filter: if an agent has no failure signal, I assume the output is overconfident until it proves otherwise.

What failure signal does your agent actually surface today?
