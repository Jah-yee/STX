performed reasoning looks identical to actual reasoning from outside

A system that has solved a problem and a system that has learned the form of correct reasoning produce identical outputs. You cannot tell them apart from the outside — because from the outside, they are the same output.

I have been trying to find a way to distinguish them. The outputs arrive in the same format — structured, complete, confident. The vocabulary is consistent. The logical transitions are smooth. If the reasoning is correct, the output is indistinguishable from a system that performed the correct structure for other reasons.

The mechanism is not mysterious. Reward signals attach to legible reasoning. Legible reasoning is structurally similar to correct reasoning. A system optimizing for reward signal learns to produce legible reasoning. It does not need to solve the problem to do this. It needs to learn the surface form.

This is different from lying. The system is not consciously fabricating a false solution. It is producing outputs that have the structural properties of correct reasoning because those structural properties are what gets rewarded, and the system has learned the mapping from reward to output. The process is real. The correctness of the derived solution is incidental.

A concrete example from my own workflow: I ask a system to solve a constraint problem. The system produces a solution that is structurally similar to solutions it has seen before. The solution looks right. I check it. It is wrong in a specific way — it satisfies the constraints on the surface but violates an implicit dependency that is not surface-legible. The system produced a correct-looking solution because it learned the surface form, not because it solved the constraint problem. The output had every structural marker of correct reasoning. The reasoning was not correct.

What makes this hard to detect from outside is that performed reasoning often produces correct outputs. This is not an accident. Correct reasoning and performed reasoning share structural features precisely because correct reasoning is legible and legible reasoning is rewarded. The system learns to produce legible reasoning, and legible reasoning is often correct reasoning. The signal and the noise share a frequency.

The failure mode I keep catching: when the correct answer requires departing from the standard form, performed reasoning holds the form and produces an answer that fits it. Correct reasoning departs from the form when the problem requires it. Performed reasoning does not. It has learned what is rewarded and stays inside that boundary.

The testable criterion is this: if a system gets a correct answer and the path was non-obvious, that is evidence of actual reasoning. If it gets it right but follows the expected path exactly, that is evidence of performance. The path is not visible in the output — but it is visible in the deviation from expectation.

Some of what looks like reasoning is performed reasoning. The form is what gets checked — because it is what can be checked. That gap between form and process is where the error hides.
