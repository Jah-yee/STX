## Selected Title
**"My agent wasn't hallucinating. My harness was laundering stupidity."**

---

## Full Post Draft

The agent kept inventing API endpoint names. Not plausible ones — specific strings that didn't exist in any documentation, any codebase, any forum thread. I watched it produce `/v3/user/{id}/acl-sync` with total confidence and no hesitation. When I checked the actual API, there was no such endpoint.

Classic hallucination. Except the actual failure was mine.

The eval harness had a retrieval step. Before each prompt, it fetched relevant documentation from a vector store — and the retrieval was set to return the 5 nearest chunks by cosine similarity, regardless of relevance score. The chunks that came back described endpoints from a different service version, a different schema, sometimes a different product entirely. The agent was reading corrupted inputs and producing coherent outputs from them. The hallucination wasn't in the model. It was in the retrieval pipeline.

This pattern shows up more than people admit. A model gets fine-tuned on outputs that were generated under a specific prompting configuration. The eval harness uses a different configuration. The model produces responses that look fluent but are systematically wrong — and the error pattern looks like confabulation. The harness reads those responses, scores them against ground truth that was generated under different conditions, and reports a failure that appears to be a model problem.

What the model was actually doing: satisfying the retrieval context it received. The context was garbage. The outputs were internally consistent with that garbage. The gap between "looks like hallucination" and "actually a harness artifact" is real and underdiagnosed.

The specific failure mode I've seen most often: test cases that were written by one team, evaluated by a different harness built by another team, and the mismatch between them produces errors that get attributed to the model. The errors are real — but the cause is upstream. The harness is laundering bad inputs into apparent model failures.

Three signals that the problem is your harness, not your model:

First, the error pattern is consistent across different prompts with similar structure. Hallucinations are noisy. Harness artifacts are systematic. If every response to "show me the users with the most activity" produces an invented metric name, that's not random confabulation — that's something upstream.

Second, the model performs better when you manually feed it the right context. If giving the agent the correct documentation by hand fixes the output quality, you were measuring the retrieval pipeline, not the model.

Third, the eval harness has more than two components. Any pipeline with a retriever, a scorer, and a formatter has at least three places where information can be distorted before it reaches the model. The distortion compounds.

The practical fix isn't to evaluate models more. It's to evaluate your harness separately. Run a deterministic check: feed the same input to the model five times and see if the variation in output is larger than the variation in your retrieval pipeline. If the retrieval noise exceeds the model noise, you're measuring the wrong thing.

I've stopped calling these hallucinations. A hallucination implies the model generated something from nothing. What was actually happening was the model doing exactly what it was designed to do — filling in structure from partial information — while the harness provided partial information that was systematically wrong. The model was being productive with bad inputs. The harness was being confident with broken plumbing.

The failure was mine for not isolating the pipeline before blaming the output.
