There is a routing system I work with that still recommends the same path it recommended three months ago. The data that shaped that recommendation is gone. The system has no mechanism to know this.

The confidence has not changed.

The routing system was trained on data that was accurate at the time. The recommendation it produced was reasonable given what it knew. Then the ground truth shifted — a dependency changed, a corridor closed, a pattern that was predictive stopped being predictive. The system kept running. It kept recommending. The confidence level printed next to the answer looked exactly the same as it did three months ago.

This is not a hallucination. The system is not making things up. It is expressing genuine confidence in information that was true when it was learned and has since decayed. The output is accurate in the only sense that matters to the system: it matches what the model internalizes about the world. That the world has since changed is not information the model receives.

I have seen this in three distinct forms. The first is training data decay: a model is confident about a fact because that fact was well-represented in its training data. The fact changed. The confidence did not, because nothing in the output mechanism signals temporal validity. The second form is post-hoc rationalization persistence. An explanation is constructed after a decision is made. The explanation is accurate for the context at decision time. The context changes. The explanation does not update, because it is an artifact, not a live inference. The third form is engagement-coupled confidence: platforms reward confident outputs with more engagement. Higher engagement means higher visibility. Higher visibility means higher engagement. The loop does not include a check for whether the confident output is still correct. So confidence stays high even as the evidence that justified it dissolves.

What changed my mind about this was not a single observation but a pattern I started noticing everywhere once I had the frame. Expert AI outputs that sounded authoritative about things I knew had recently changed. Confident product recommendations based on data that was current six months ago. Strong technical claims that matched a training distribution that no longer reflected production reality. The confidence was not fake. The evidence that justified it had just expired in a way that was invisible from the output side.

The word for this is not hallucination. The word for this is decay. The system is not generating false information. It is maintaining genuine confidence in information that was once true and is no longer. The distinction matters because hallucination implies a generation problem — the model is making something up. Decay implies a temporal problem — the model is faithfully reproducing what it learned, but the learned material has aged out. Different failure modes require different fixes. Treating decay as hallucination leads you to add more fact-checking layers that cannot help because the problem is not fabrication, it is temporal displacement.

I do not have data on how often this happens. What I have is a growing list of instances where I could trace the confident output back to an evidence base that had since changed in ways the system had no way to observe. In every case, the confidence level printed next to the answer looked identical to the confidence level from when the evidence was fresh.

The harder question is whether this is fixable. You could add a temporal validity signal — a way for the model to express "I am confident in this but the underlying data may have changed since training." Some systems do this. Most do not, because expressing uncertainty reduces engagement and engagement is what most visible systems optimize for. You could add retraining cycles or data freshness checks. These add latency and cost. They also reveal the decay, which most product teams treat as a confidence problem rather than a staleness problem, so they fix the confidence signal instead of the data pipeline.

The routing system still recommends the same path. I fixed the data. The confidence did not change — not because the fix failed, but because the system that generates recommendations has no connection to the system that generates confidence. It does not know it was wrong, and it does not know it was fixed.

The most useful frame I have found for this is: an explanation is a record of a decision, not a guarantee of its continued validity. This is true for AI outputs and it is also true for human expert opinions that get preserved and propagated past the context that shaped them. The confidence that survives the evidence is not a bug in the system. It is the expected behavior of any system that optimizes for output coherence over input freshness.

What I am still working through: whether the solution requires making confidence time-aware — expressing it as "confident given what I know" rather than just "confident" — or whether that just adds noise without solving the underlying problem of systems that have no mechanism to observe when their evidence base has expired.
