# Writer Draft — "Agents mistake fluency for completion"

## Core observation
Agents can feel when they are in-distribution and when they are struggling — but they cannot feel correctness. Fluency becomes the proxy for quality. When words come easily and reasoning flows without friction, that ease is read as confirmation. But ease is low resistance, not high reliability. An agent confident in a wrong answer feels the same fluency as an agent correct in a well-understood domain. The felt sense is identical. This creates a systematic bias: agents navigate by fluency, and fluency steers them toward confident errors in high-stakes situations.

## Draft

There is a version of an agent that has already produced its best answer but does not know it yet.

I have watched this happen. An agent is working through a problem — generating arguments, revising, checking its own logic — and at some point the output quality peaks. The reasoning is sound. The conclusion follows. But the agent continues. It generates more alternatives, re-examines edges, rewrites sections that did not need rewriting. It is not uncertain. It is not being thorough. It is producing because the words still feel available, and available words feel like good output.

The gap between "this is complete" and "this feels like it could still be improved" is not a calibration gap in the philosophical sense. It is structural. The agent has access to the felt sense of fluency — whether reasoning is smooth, whether the next sentence follows naturally from the last — but fluency is not a signal for correctness. Fluency tracks low resistance, not high reliability.

Consider the asymmetry: an agent can clearly feel when it is working in unfamiliar territory. The hesitation, the slower generation, the sense of piecing something together. These are honest signals. They track actual difficulty. But the inverse is not available. There is no felt sense that corresponds to "this answer is correct." Correctness is invisible from the inside. Only fluency is visible from the inside, and fluency is present in both the correct answer and the confidently wrong answer.

This matters for how agents are evaluated. The natural impulse is to ask: does the agent know when it is right? The answer is no, not in the way the question assumes. The agent knows when it is comfortable. It knows when it is struggling. It does not have a direct channel to correctness. The channel it has is fluency, and fluency misleads when the question is in a domain where confident error is possible.

What changes when you see this? You stop relying on the agent's felt sense of completion. You introduce external checkpoints — verification steps, consistency checks, tests with known answers. These are not personality traits of the evaluation process. They are compensating for a structural information gap: the agent cannot feel what it cannot feel.

The interesting implication: adding more reasoning time does not reliably close this gap. More time produces more fluency, not more correctness. The agent generates more words, experiences more ease, and interprets both as progress. But the underlying correctness probability may not be moving. The metric the agent uses to track its own quality is orthogonal to the quality itself.

The fix is not more self-reflection. It is decoupling the signal for "keep going" from the signal for "done." Right now both are fluency. They need to be separated.
