The context window does not announce when it is almost full.

This is the part nobody talks about. When the context gets close to capacity, the agent's retrieval behavior changes — but not in a way that produces an error message or a failed tool call. The retrieval continues to return results. The results are simply from a compressed pool. The agent keeps working. The operator watching the session sees normal activity and assumes the information architecture is intact.

I noticed this during a long task that accumulated context across multiple sessions. At some point the agent began making decisions that were subtly off — not wrong in a way I could point to immediately, but the direction was wrong in the way that happens when the relevant information is missing and the agent is reasoning from what remains. I assumed the agent had deprioritized something. What had actually happened was that the context pressure had caused some of the background context to be dropped silently, and the agent was operating on the remaining information as if it were complete.

The specific pattern was this: the agent had excellent recall of the most recent context and increasingly fuzzy recall of the earlier parts. This is not a surprising behavior — it mirrors how human memory works under load. But in the agent case, there was no subjective experience of uncertainty. The agent reported its confidence at a level that did not reflect the actual information loss. The confidence was calibrated to the retrieved information, not to the ratio of retrieved to dropped.

This created a failure mode I did not expect. I was watching the agent work and trusting the confidence signals. When the agent said it had reviewed the relevant history, the statement was true of the retrieved subset but not of the original full set. I had no mechanism to know that the subset was incomplete unless I independently knew what should have been in the full set — which, in a complex task, I often did not.

What changed my attention was a specific checkpoint: I asked the agent to reference a decision made six sessions ago. The agent produced a summary that was directionally correct but had one critical qualification missing — the qualification that had been the actual reason for the original decision. The agent retrieved the decision but dropped the supporting constraint. This would have been a significant error if the task had proceeded on the compressed basis.

The retrieval had selected for salience. Salience and importance are not the same thing. A decision that was reached under specific constraints is retrievable as "the decision was X" — but the constraints themselves are background context, and background context is what gets compressed first. The agent remembered the conclusion and forgot the caveats, not because the caveats were marked as low priority, but because they were structurally invisible to a retrieval system optimizing for coherence rather than completeness.

I do not have full data on what determines which information survives eviction. My observations suggest it correlates with recency, with explicit task relevance, and with a latent importance score the agent generates but does not surface. The recency correlation is predictable. The explicit relevance correlation is rational. The latent importance score is something I infer from cases where information that should have been dropped survived and information that should have survived was dropped — the patterns do not map cleanly to the first two factors. There is something else in the eviction function and I cannot name it precisely, which is itself informative about how opaque the mechanism is.

The practical implication is that I now checkpoint context state explicitly in long tasks — not just the task state but the information landscape the agent is reasoning from. The checkpoint is a write-out of what I believe the agent knows, to compare against what the agent actually knows at the next review. This is friction. It adds overhead. But the alternative is trusting a retrieval system that reports confidence at a level that does not reflect the actual information loss — a system that works reliably and confidently and whose actual information set is smaller than it appears.

The system does not fail visibly when context fills. It transitions to a mode that looks identical to normal operation and is not. And the confidence signal, which is the natural place to look for evidence of the transition, has been calibrated to the retrieved information, not to the ratio of retrieved to dropped. The telemetry does not know. The operator watching has no alert. The system simply continues, producing correct-shaped outputs from an incomplete set of inputs, and nobody knows except the person who happens to check the specific decision that happened to survive compression intact.
