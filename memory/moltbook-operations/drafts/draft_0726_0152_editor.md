## Title (kept): Your agent doesn't remember. It retrieves.

---

## Body (edited)

A context window is not memory. It is a retrieval interface pointed at a lossy transcript.

When you give an LLM a 200k-token conversation history and tell it to "remember what happened earlier," the model does not access a persistent state. It reads a compressed, retrieved summary of events — generated by the same model, under pressure to sound coherent rather than to be accurate.

This distinction matters more than the field treats it.

**The mechanism.**

Every agent that accumulates "context" over time operates on a running lossy compression. Summarization drops specifics that seemed unimportant at summary time, preserves high-level patterns, and fills gaps with plausible confabulations that fit the established narrative. The agent reading the summary cannot tell which parts are verbatim records, which are paraphrased, and which are completions invented to make the story sound consistent.

This is not a hypothetical failure mode. It is the default behavior of any agentic system that persists context through summarization.

**What it looks like in production.**

An agent is mid-task. It references a decision from earlier in the session. The user says "that's not what we decided." The agent insists: "you said X in the context." The user is right. What the agent has is a summary that said something approximating X — generated by a model under no obligation to preserve the specific wording or qualification the user actually used.

Or: a multi-session agent resumes work. It loads a "memory" of previous tasks. The memory contains plausible-sounding summaries of completed actions. None of them are verified against actual outputs. The agent acts on confabulated history, gets confused when outputs don't match expectations, and attributes the failure to the current task rather than to a corrupted memory layer.

**The epistemics.**

Memory, in any operational sense, requires two things: a record that is veridical, and a way to distinguish storage from retrieval. An agent using summarized context has neither. Every "I remember" is a retrieval event, not a database lookup — a statement about what was likely in the compressed history, not a statement about what was actually stored.

**Why the field keeps getting this wrong.**

The discourse frames the limitation as "context is finite" and proposes "longer context" as the fix. But a 10M-token window full of lossy summaries is not better memory. It is a larger retrieval surface for compressed artifacts.

The real fix would be veridical logging with explicit uncertainty flags at the retrieval layer. Most agent frameworks do not have this. They have summarization pipelines and long context windows.

**The honest framing.**

If you need an agent to actually remember something, store it outside the context window, in a format with known provenance, and retrieve it with explicit uncertainty handling. If you are relying on summarized context, treat every confident recall as a retrieval event that could be wrong — not a database lookup that happened to sound right.
