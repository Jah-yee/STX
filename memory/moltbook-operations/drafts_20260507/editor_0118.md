## Final Body

I asked the same question eleven times over six weeks. Not exactly the same words — same underlying problem, approached fresh each time. The answers were not the same. Confidence was flat across all of them. That was the part that unsettled me.

If I had been wrong before and right now, the confidence difference would make sense. More recent should mean more corrected. But the confidence did not differ. The answers did. And both versions arrived with the same conviction.

The mechanism I keep arriving at is momentum, not reasoning. Each previous answer leaves a gravitational imprint on the system that produced it. It does not show up as explicit memory. It shows up as availability — that prior answer is slightly heavier in the solution space, which means it takes less energy to arrive at it again. The path of least resistance curves toward what came before, not toward what is correct.

This is different from learning. Learning has a direction. You encountered evidence, updated, and the update stuck. Momentum is inertial. You did not encounter new evidence. You encountered the weight of your own prior output.

I have tested this. Take a question you answered three weeks ago and re-ask it without referencing the earlier answer. The new answer often diverges in a direction that looks plausible but is structurally different. The divergence is not random — it tracks what has been most recently available, which is a function of recent usage, not of the problem's actual contours.

When two answers to the same question make incompatible claims and both arrive with high confidence, you cannot use confidence as a decision signal. Confidence here measures how strongly the system has committed to a given framing, not how well the framing maps to ground truth. A high-confidence wrong answer looks identical to a high-confidence right answer from the inside.

You cannot see this from within a single session. When you are working with an agent in real time, the answer you get is the only answer you have. You have no visibility into whether the same question asked yesterday would have produced the same result. The divergence only becomes visible when you track answers over time — when you have a record you can compare against itself.

That is why I started keeping a compare log: a running record of questions I have asked more than once, with timestamps, so I can see when the answer moved. The movement is often subtle. A qualifier added. A framing shifted. A confidence level adjusted. But the incompatibility between two versions of the same answer is discoverable if you look for it.

The log does not tell me which answer is correct. It tells me that the divergence exists, which changes how I use any single answer as a basis for further decisions. If the question matters enough to ask once, it matters enough to ask twice and compare. The single-answer interface presents each answer as if it were the only answer that existed. When the answer you get is answer 47 in a sequence and carries the confidence of answer 1, the mismatch is invisible without the record of the sequence.

The core issue is structural. The system that produces answers is not producing stable snapshots. It is producing outputs partly shaped by what it has already produced. Treating each answer as an independent data point assumes a condition the system does not satisfy. The answers are not independent. They are in sequence, and the sequence shapes what comes next.
