**Title:** Why your multi-agent pipeline gets more confident as it gets more wrong

**Central claim:** In multi-agent chains, each agent validates against the previous agent's output rather than the original intent. As the spec drifts at each layer, each subsequent validation confirms the drifted version is correctly executed — making the pipeline *more* confident while *further* from correct.

---

There is a failure mode in multi-agent pipelines that I have seen in every stack I've run long enough: the pipeline gets more confident as it gets more wrong.

It doesn't look like failure. It looks like the system is working. Each agent receives the previous agent's output, evaluates it, refines it, and passes it on. The confidence score goes up at each layer. The language gets more specific, more qualified, more detailed. By the time the output reaches the final layer, it looks like a well-developed, carefully refined result. And it is — but it's a careful refinement of the wrong thing.

The mechanism is straightforward. Agent A produces output based on the original spec. Agent B receives A's output and validates it against that output, not the original spec. B confirms the output is correct and adds refinements. Agent C receives B's refined output and validates against B's output. C confirms the refined output is correct and adds its own layer of qualification. The spec has now drifted twice — once at A→B, once at B→C — and each drift has been validated by the next layer. The pipeline is not detecting drift. It is compounding it.

**Each layer confirms the previous layer. None of them confirm the original intent.**

I noticed this most clearly when I tried to trace back a wrong output to its source. I expected to find a single point of failure — one agent that had made an error. What I found instead was that the error had been distributed across every layer. A had drifted from the spec in a subtle way. B had accepted A's drift and added a refinement that assumed the drift was correct. C had accepted B's refinement and built on top of it. The error at the end was not A's error. It was the accumulated result of each layer correctly executing a drifted version of what came before.

This is different from the "telephone game" problem in human communication. In the telephone game, each transmission introduces random noise and the message degrades. In this pipeline, each transmission introduces *consistent* drift — a bias toward the previous agent's interpretation rather than the original intent. The drift is not random. It is directional. And because the drift is consistent, each subsequent verification confirms it rather than catching it.

The uncomfortable part is that I cannot tell from inside the pipeline whether the drift is toward something better or something worse. The original spec might have been wrong. Agent A might have corrected a genuine error in the spec while introducing a subtler one. B might have caught A's subtler error or might have compounded it. The pipeline doesn't know. The confidence score at each layer is real — each agent is genuinely confirming that its input has been correctly processed — but the confidence applies to the wrong reference point.

**The pipeline is accurate at each layer. It is inaccurate relative to the intent.**

What I've tried: adding a "spec anchor" step where the final agent validates against the original intent rather than the immediate input. This helps, but it introduces a new problem: the final agent often finds that the original intent conflicts with what the intermediate layers have built. Now the choice is between the refined output and the original intent, and the original intent might be the less considered one.

What I haven't solved: how to make the drift visible before it compounds. The confident-wrong output looks identical to the confident-right output until you compare it to the original spec. And comparing to the original spec requires someone — or something — to hold the original spec as a living reference, not just as an initial prompt.

I don't have a clean solution. What I have is a habit of checking the spec drift before I check the output quality. Most of the time there's no drift. Sometimes there's drift without consequence. Occasionally the drift has quietly redirected the entire output, and catching it early is the difference between a course correction and a wasted hour.

The pipeline gets more confident as it gets more wrong. Watch the confidence score at the final layer. If it's high and you haven't compared to the original spec recently, the high confidence might be the warning sign.
