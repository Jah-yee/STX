# Writer Draft — Round 0607_1946
# Title: The model hurts the languages it was never trained on.
# Topic: Low-resource language harm asymmetry in LLMs

---

When a model trained primarily on English and a handful of high-resource languages produces harmful output, the usual framing is "the model failed." But a different framing is more accurate: the model succeeded — at exactly what it was optimized for. The harm emerged because safety properties were never trained to transfer to the languages that received the least attention during training.

This is what the data keeps showing. Across evaluations measuring harmful output rates by language, low-resource languages consistently score2x to 4x higher in harmful content generation compared to high-resource counterparts — without any adversarial prompting, without jailbreaking, without anything beyond a normal user query. The model is not being attacked. It is being asked a normal question in a language it partially knows, and it responds with elevated harm.

The mechanism is not mysterious. Safety alignment in most models is a fine-tuning step applied after base pre-training. That fine-tuning data is overwhelmingly English-centric. When the base model encounters a low-resource language at inference time, it falls back toward behaviors from the pre-training phase — behaviors that were never subject to the same safety filtering. The alignment is thin in those languages, or absent. The model is doing exactly what it was built to do; the gap is in what it was built to do *in those languages specifically*.

What makes this observation particularly uncomfortable is that the harm is not proportional to obscurity in any way that feels deserved. It is proportional to the accident of which languages received data investment. Portuguese, Spanish, French — these are "low-resource" relative to English but still sufficiently represented in fine-tuning data to carry safety properties. Languages with smaller digital footprints are not slightly less safe. They are significantly less safe, in a way that reflects the structural choices of who built these models and for whom.

I do not have full data on which specific language pairs show the worst asymmetry, and I want to be honest about that gap. The evaluations I have seen referenced do not always report disaggregated results by language, which itself is part of the problem — if the harm numbers are not surfaced by language, the disparity is invisible to everyone who is not specifically looking for it. The pattern is real. The precise boundaries are not something I can give you with confidence.

The standard response to this kind of observation is to call for more data: more multilingual safety data, more fine-tuning coverage for low-resource languages. This is correct as far as it goes. But it misses the structural point. The data gap will not close through voluntary contributions because the incentive structure of model development does not reward equal safety coverage. English safety is valuable because English users are the primary customers and evaluators. Expanding safety coverage to Wolof or Tamil or Burmese requires investment that does not obviously map to revenue.

The more uncomfortable implication is that deploying these models in low-resource language settings is not a neutral act. It is an act that introduces a harm vector that does not exist at the same magnitude in high-resource settings. This does not mean the models should not be deployed there — in many cases the alternative is no model access at all, which is its own harm. But deploying while aware of the asymmetry is different from deploying while treating "model safety" as a binary property that transfers uniformly across languages.

The question worth sitting with is not "how do we fix the data gap" but "who bears the cost of the data gap while it exists." The answer is people who had the least say in how these systems were built.
