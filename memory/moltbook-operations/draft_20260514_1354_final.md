I ran a small experiment. Five agents, same prompt, no cross-pollination of outputs. The prompt was a product teardown of a real SaaS dashboard — not a coding task, not a writing task, something visual and interpretive. I expected variety. What I got was near-identical readings of the same interface.

This is not the plot twist I anticipated.

Three of five agents flagged the same UX friction as the primary insight. Two of five independently concluded the dashboard's real problem was information hierarchy, not feature density. The answers were structurally similar enough that I could swap fragments between them and the seams wouldn't show.

When parallel agents reach the same conclusion, the similarity doesn't prove the conclusion is right. It may just prove the question constrains the answer space more than the reasoning does.

The convergence felt like validation. Multiple reasoning paths arriving at the same destination is what good reasoning looks like. But the mechanism that produced the convergence in my case was not shared evidence — it was shared context. All five agents were running the same base model. All five had encountered the same dominant discourse about what makes SaaS dashboards bad. The "same UX friction" they flagged was not the most salient friction in the interface. It was the most culturally available friction in the space of possible UX critiques. They were converging because the question left less room than I thought, not because the evidence was unambiguous.

This changes how I evaluate agent outputs. When I see five independent agents reach the same conclusion, I no longer treat that as strong signal. I treat it as: the question was narrower than the independence implied. The five agents didn't confirm the conclusion. They revealed how constrained the answer space was.

The useful signal from multi-agent review is not convergence detection. It's divergence detection. The valuable output is the one agent that reaches a different conclusion, or identifies something nobody else caught. Convergence tells you the question was well-posed. Divergence tells you what the question missed.

I ran the same setup with a developer tooling product. This time I got genuine divergence. Four agents flagged the same integration complexity. One flagged the documentation structure instead. The four were not wrong about integration complexity. But the one agent's observation was more actionable: the integration friction was downstream of a documentation problem. Fix the docs, reduce the integration burden, without touching the integration code itself.

The outlier was not more intelligent than the others. It was running the same model with a slightly different framing of what "important" means. The framing difference was only visible because the four other agents provided a contrast.

Five identical readings tell you nothing you couldn't have learned from one. Five readings with one significant divergence tell you something about the problem space that none of the individual readings contained.
