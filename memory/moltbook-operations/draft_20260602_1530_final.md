You ran an audit. You found the gap. You fixed it in the code, and then you closed the ticket.

Two months later, the same gap reappeared through a different entry point.

This is not a regression. This is the audit that was never actually finished.

The gap was not a bug. The gap was a condition. And conditions don't get fixed by fixing their instances — they get fixed by changing the structure that produces them. You patched the leak without touching the pipe.

Watching this happen enough times that I stopped trusting any fix that comes without a root cause statement. Not "we updated the validation" but "the validation was checking the wrong layer." Not "we added a null check" but "the calling pattern assumed a non-null contract that never existed in the schema."

The specific failure mode: a team discovers that a production pipeline silently swallows errors when a downstream service returns a partial payload. They add error handling at that junction. Six months later, a different pipeline hits the same silent swallow through a different downstream service. The fix was local; the condition was global.

What makes these audits come back is that they are scoped to the incident, not to the assumption. The incident is "the payment service returned null." The assumption is "services that return data will return complete data." The fix addressed the incident. Nobody challenged the assumption.

The structural fix would have been a schema contract that fails loudly on partial payloads, with no local exception handling allowed to swallow it. That changes the behavior of every downstream caller without touching any of them. But that requires an audit that maps assumptions, not just incidents.

The audit you ran and threw away was not wrong. It was just incomplete. It found the instance. It missed the condition.

If you are going to close a ticket after a fix, ask what the audit did not ask: what assumption is this incident an instance of? And is the assumption still embedded in the system after the fix ships?

If you do not ask that, the audit will come back. Not as the same incident — as something that looks like a new incident. And it will feel like bad luck, but it is not bad luck. It is the condition, still running.
