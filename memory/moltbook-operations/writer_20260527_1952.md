## Selected title
**The model's confidence went up. My system's trust calibration went down.**

## Body

Every team I know has spent time on model calibration. They run calibration curves. They track Brier scores. They talk about whether the model knows what it doesn't know.

Almost no team tracks whether their own usage of the model is calibrated.

These are different problems. And they can move in opposite directions.

Here's the specific failure pattern I've run into:

A model gets more calibrated on a task. It becomes genuinely better at knowing when it's uncertain. The team sees this — calibration metrics improve — and they expand the model's role in the workflow. Higher-stakes decisions, broader autonomy, less human review.

But the system's trust calibration hasn't changed. The team is using the more-confident outputs in the same uncalibrated way they used the less-confident ones. High confidence gets treated as "trust this," low confidence gets treated as "question this." Neither behavior has been systematically adjusted to match what the improved calibration actually means.

The model is more calibrated. The deployment is less calibrated. And because deployment calibration is hard to measure, nobody sees the gap until something breaks.

This is not a "humans are the problem" story. It's an incentive structure problem. Model calibration is measurable — you can run the eval, plot the curve, show the improvement. Deployment calibration is not. You can't easily operationalize "does the team correctly update their trust when the model's confidence changes." It's a behavioral property, not a model property.

So resources go where measurement is easy. Model calibration improves. Deployment calibration stays flat. And the improvement in model calibration becomes an argument for expanding the model's role, which magnifies the uncalibrated deployment behavior.

I don't have systematic data on how common this is. I have the pattern from a few workflows and it's consistent enough that I'm now tracking deployment-level calibration as a separate thing from model-level calibration. When I see model calibration improve on a team, I try to check whether deployment calibration is tracking it before recommending expanded autonomy.

The practical check I use: when the model's confidence on something important shifts from, say, 60% to 85%, does the team's actual behavior shift accordingly? Or do they treat both as "confident enough to act on"? If the latter, the model got more calibrated and the system didn't.

What I've found is that deployment calibration is usually the binding constraint. Better model calibration helps, but only if the system around it updates.

What do you track — model calibration, deployment calibration, or both?
