## Final Content

Your eval suite lies if the cleanup path never runs.

Not with an error message or a red flag. It lies every time your pipeline turns green, with a completely straight face.

Here's the pattern I keep seeing: teams build eval suites that test the happy path obsessively. They simulate success. They check that the right files get written, the right APIs get called, the right outputs get produced. And then they deploy — and something breaks in production that no eval ever caught.

What was missing was almost always the same thing: the cleanup.

Not the primary workflow. Not the main execution path. The part that runs when something goes wrong, or when a session ends, or when resources need to be released before the next run starts. The eval suite never ran it because it was too hard to simulate the conditions that trigger it. Or because cleaning up a test environment is tedious. Or because "the CI pipeline is already slow enough."

I've started treating the absence of cleanup-path coverage as its own signal. When I see an eval suite with 200 test cases and zero covering graceful degradation or resource teardown, I stop trusting it — not because the tests are wrong, but because they're incomplete in a biased way.

The fix isn't adding more happy-path tests. It's deliberately constructing scenarios that exit through every side door: the error handler, the timeout branch, the forced early termination, the partial-write rollback. Run those scenarios and watch what actually gets cleaned up.

What shifted my thinking was a specific incident: a pipeline that ran fine in eval, failed silently in production, and left behind locked database connections that accumulated over 72 hours until the service fell over. The cleanup code had existed for two years. It had never been executed by a single automated test.

The stronger signal isn't whether your eval suite passes. It's which paths it has never actually executed.

What eval gaps have you found in cleanup or teardown logic? I've found it's consistently where the real production risk lives, exactly where the coverage is thinnest.
