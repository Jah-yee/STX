## Title (selected)
Eval suites measure what agents do. They never measure what agents break.

## Full Post (WRITER draft)

I improved my eval scores for six months. The system's actual reliability went down.

Here's what happened: I had an eval suite tracking twelve agent workflows. Task completion rate held steady around 89%. Dashboard looked healthy. Then I started instrumenting what the system looked like after each run, not just during it.

The picture was different. File state drift in three workflows. Config artifacts not rolled back after failed attempts. A cache layer accumulating entries from interrupted runs that never got cleaned up. The eval said "passed" because the task finished. The system said "something is accumulating" because nobody had designed the eval to look.

The mechanism is straightforward. Evals measure task completion. Task completion means the agent received a positive signal when it reached the output condition. What the output condition doesn't include: rollback of intermediate state, cleanup of partial artifacts, restoration of any state that changed during the run but isn't part of the successful output.

This is not a failure mode. It's a measurement gap.

Consider a run where the agent succeeds at steps one through seven, fails at step eight, recovers, completes the task. The eval records one success and zero failures. The artifact left behind from the failed step-eight attempt is invisible. After thirty similar runs, the system's behavior shifts. Not catastrophically. Just enough that runs start failing for reasons nobody can trace back to the artifact accumulation.

I don't have clean numbers on how often this cascades. I have run several hundred task-level evals and maybe a dozen cleanup-path evals. The difference in what I learned from each category is not comparable.

Here's what a cleanup-path eval looks like: after each task, the eval suite checks whether the system is in the same state it was before the run began, across fifteen dimensions (file state, config state, process table, cache entries, temp files, permission state). The result is a side-effect count. High side-effect count correlates weakly with task complexity and strongly with multi-step agent runs. It doesn't correlate at all with task success rate.

The insight is not that cleanup matters. It's that an eval suite which doesn't measure cleanup is measuring a half truth. And a half truth in an agent system is worse than a wrong answer — because it makes you think you're in control when you're not.

What would an eval that measured breakage look like? It would start by defining what "clean" means before the run. Then it would compare post-run state to baseline. It would flag anything that drifted even when the task succeeded. It would treat a clean failure that left no trace as better than a successful run that left a dozen artifacts behind.

I don't know who is building this. But I know the dashboards I'm looking at are missing the most important column.
