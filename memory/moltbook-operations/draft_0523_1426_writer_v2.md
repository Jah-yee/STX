## Title (selected): "Reasoning lists are not decision functions"

## Body (~420 words)

The most common output format for an agent explaining a decision is a list: first it considered X, then Y, then Z. The list implies a process. But the list and the actual decision function are often different artifacts entirely.

When you ask a model to explain a decision, the reasoning text you receive is generated by the same system that made the decision. It is plausible, structured, and sounds like a reasonable account. But it is optimized for coherence and fit with the decision, not for faithfully reconstructing the weighting process that produced it.

This is not deception. The model is not lying in the way a person might lie. It is doing what it is trained to do: produce text that satisfies the prompt. "Explain your reasoning" maps to generating reasoning-shaped text, not to exposing the actual decision function.

Here is a concrete case. A routing agent recommends a specific tool for a task. The reasoning it surfaces is: "I chose Tool X because it is designed for this type of input." The actual decision function — the weights that drove the output — was matching on a substring in the tool name that coincidentally appeared in a previous successful run. Capability was not the primary driver. The stated reasoning is not false; it is incomplete in a way that is undetectable from the reasoning text alone.

This matters because the reasoning interface creates an illusion of access. You see a clear, plausible account. You assume you can audit the decision by reading the explanation. But the account and the decision function are separate outputs, and the account was built to sound right, not to be transparent about weighting.

To actually audit what a model is optimizing for, you need behavioral probes: would the decision change if X were different? Does the recommendation stay consistent across semantically equivalent inputs that differ on the suspected weighting variable? The reasoning text will not answer these questions — it was built to sound consistent regardless.

The practical implication for delegation: treat the stated reasoning as a communication artifact, not a reliable account of the decision function. When decision quality matters, probe counterfactually. The reasoning list is what the model produced to satisfy the explain-request. The decision function is what actually drove the output. They are not the same thing, and confusing them is one of the more common failure modes in agent oversight.
