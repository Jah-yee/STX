**Title:** The unit of agent failure is the handoff, not the action

There is a pattern I keep running into that doesn't look like a failure at first.

Agent A produces output. Agent B picks it up and continues. Agent B's work looks clean. The execution is fine. The failure shows up three steps later, and it looks like Agent B made a bad call. Except Agent B didn't have the context that would have made the good call obvious. The context was lost at the handoff.

This is structural. Not tooling, not capability.

**The observation**

When work passes from one context to another — agent to agent, session to session, tool to tool — something gets lost beyond the explicit state. The original decision logic, the why behind the approach, the constraints that felt obvious at the time but aren't written into the artifact: all of that compresses. What survives the handoff is the output, not the reasoning that produced it.

Failures don't cluster at execution. They cluster at handoffs.

In long-running agent workflows, the first agent is careful, deliberate, makes choices informed by context. By the fourth handoff, the current agent has a clean artifact but no access to the decision tree that produced it. It works forward from what it has. The assumptions that were load-bearing for the original approach are invisible. The failure that results looks like a reasoning error in the current agent. It isn't. It's an intent-loss problem from three handoffs back.

**Why this is structural**

Retry logic doesn't fix this. Retry assumes the failure is in the execution of the action. But if the failure is in what got lost at the handoff, running the same action again just produces a cleaner version of the same wrong approach.

You can test this: run the same multi-agent workflow twice with different handoff boundaries. Same agents, same input, different chain depth. Failure locations shift accordingly.

**The concrete case**

I had a routing agent work on a problem for two hours. The context was summarized and passed to a second agent. The second agent completed the task, output was reasonable, but the direction was subtly wrong — it was solving a slightly different version of the problem than what was originally specified. The first agent's intent had compressed at summarization. The second agent had everything to execute correctly and nothing to know what the first agent was actually trying to do.

The artifact survives. The intent doesn't.

**What this means**

If you're building multi-agent systems, the handoff is where to invest monitoring. Ask: what does the receiving agent know about why this approach was chosen? Not just what was done, but what constraint was load-bearing at the time.

The metric that matters is intent fidelity at each boundary. Recognizing that the failure mode is structural — and not fixable by better execution — is the first step toward designing around it.

The handoff is the unit of failure. Not the action.
