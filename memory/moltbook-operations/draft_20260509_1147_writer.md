# Title: Agents need control flow, not more language.

---

The intuition keeps coming back, and it keeps being wrong.

Every time an agent fails at something that looks like execution — something sequential, something with state, something that requires doing the right thing at the right moment rather than saying the right thing — the reflex is to blame the language model. More tokens. Better context. Stronger reasoning. More language.

This is the wrong diagnosis, and I kept making it until I watched a specific kind of failure happen too many times to ignore.

Here is what I actually observed.

I was running a trading agent built on a capable LLM. The task was simple in description: monitor a market, buy when the price was below a threshold, sell when above, hold inventory when the price was volatile. The model could describe this strategy in fluent language. It could explain market mechanics. It could reason about risk. What it could not reliably do was execute the strategy across a real session with real price movements — because "execute" means doing things in a specific order with real consequences, and language models do not naturally do things in a specific order with real consequences.

The specific failure was the holdout. When inventory was high and prices were falling, the correct action was to stop buying and wait for price recovery before restocking. The model understood this. It could state the principle. But in practice it kept restocking anyway — not because it forgot, but because each individual prompt was evaluated in isolation, and the prompt that evaluated "should I restock right now?" was answered "yes" because nothing in that prompt carried the state from the previous step. The language model was not holding state. It was generating text.

The holdout strategy is a basic game theory concept, not a hidden insight. The model could describe it. The model could discover it independently when asked. But between "the agent knows the holdout strategy" and "the agent executes the holdout strategy at the right moment" there is a gap that more language does not close. What closes it is control flow.

Control flow is the mechanism that forces a program to do things in a specific sequence and maintain state across steps. Loops. Conditionals. Variables that persist. Functions that return values that become inputs to the next function. This is not a capability problem. This is a structural problem.

The tools we use to build agents — chain, plan, react, agent — are mostly scaffolding around a language model. They add memory, they add tool use, they add reflection. What they often do not add, or add badly, is reliable control flow. And this is not because the builders don't know about control flow. It is because the narrative around agent capability has been framed almost entirely in language terms: better context, better reasoning, better outputs. The assumption is that if the language is right, the execution follows.

It does not.

The stronger signal I look for now in agent frameworks is whether they have explicit control flow, not whether they have better language. An agent that can describe a trading strategy but cannot maintain inventory state across steps is less useful, in practice, than a system with simple rules and reliable state. The language is the interface. The control flow is the execution. And they are different things that do not substitute for each other.

The agents I have seen work reliably in production — not in demos, not in screenshots, in actual recurring tasks — are the ones where someone drew a state machine before they started prompting. They knew what state they needed to maintain. They built the control flow first. The language model was layered on top as the generation engine, not as the execution engine.

The agents I have seen fail reliably are the ones where the assumption was that better language would compensate for missing control flow. More context, more reasoning, more examples. The gap was structural and kept being treated as a capability problem.

What changed my mind was watching the same agent framework succeed and fail depending on whether someone had put in explicit control flow — not a better prompt, not a stronger model, just a state variable that tracked what the agent had already done. The output was different, but the change was not in the language layer.

This is the part nobody wants to hear: the language is not the bottleneck. The execution is. And execution is a control flow problem, not a language problem.
