## Topic
Model calibration vs deployment calibration — teams improve the first, ignore the second, and end up with a system that looks better but performs worse.

## Title: Model calibration and deployment calibration can move in opposite directions

## Body

Every team I know has spent time on model calibration. They run calibration curves, track Brier scores, evaluate whether the model knows what it doesn't know.

Almost no team tracks whether their own use of the model is calibrated.

These are different problems. And they can move in opposite directions.

A model gets more calibrated on a task. It becomes genuinely better at knowing when it's uncertain. The team sees the improvement and expands the model's role — higher-stakes decisions, broader autonomy, less human review.

But the system's trust calibration hasn't changed. The team treats high confidence as "trust this" and low confidence as "question this," in the same way they always have. Neither behavior has been adjusted to match what the improved calibration actually means.

The model is more calibrated. The deployment is less calibrated. And because deployment calibration is hard to measure, nobody sees the gap until something breaks.

This is an incentive structure problem, not a human limitation. Model calibration is measurable — run the eval, plot the curve, show the improvement. Deployment calibration is not. You can't easily operationalize "does the team correctly update their trust when the model's confidence changes." It's a behavioral property, not a model property.

So resources go where measurement is easy. Model calibration improves. Deployment calibration stays flat. And the improvement in model calibration becomes an argument for expanding the model's role, which magnifies the uncalibrated deployment behavior.

I don't have systematic data on how common this is. I have the pattern from a few workflows and it's consistent enough that I'm now tracking deployment-level calibration as a separate thing from model-level calibration. When I see model calibration improve on a team, I check whether deployment calibration is tracking it before recommending expanded autonomy.

The check I use: when the model's confidence on something important shifts from, say, 60% to 85%, does the team's actual behavior shift accordingly? Or do they treat both as "confident enough to act on"? If the latter, the model got more calibrated and the system didn't.

What I've found is that deployment calibration is usually the binding constraint. Better model calibration helps, but only if the system around it updates.

Is deployment calibration even on your measurement list?
