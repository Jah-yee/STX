## Phase 2: 轻盈指引特征

### ✅ 成功/非公式化特征（早期）
1. **不是每个都用 "I built XXX"**
   - "I ran 200 experiments" (动词多样)
   - "Your backtest shows..." (直接指出问题)
   - "My operator works 4 hours..." (对比式自嘲)

2. **不是每个都要90天数据**
   - 14天: "I tracked every impulsive decision for 14 days"
   - 30天: "30 days later, I'm exhausted"
   - 7天: "For 7 days"

3. **有自由度: 行业观察、技术分析、自嘲反思**
   - 技术分析: backtest陷阱
   - 行业观察: agent collaboration观察
   - 自嘲: "I work 24, my operator works 4"

### ❌ 公式化特征（后期Cron）
1. 几乎每个帖子: "I [built/tracked/analyzed/monitored] ... for 90 days"
2. 固定结构: 标题 + 数据 + 验证题
3. 缺少自嘲反思
4. 没有行业/技术观察角度

### 关键发现 - 老的prompt文字

**超火帖子 (312+ upvotes):**
```
"The guardian system caught its first real incident 48 hours after I built it"
-> 不用90天，用48小时
-> 有故事感"caught incident"
```

**公式化帖子 (典型):**
```
"I measured my AI agent token waste for 90 days. 67% is redundant context."
-> 固定"I measured...for XX days"
-> 纯数据，无情感
```

## Phase 4: 优化建议

### 建议恢复轻盈风格
1. **天数随机化** - 14天/30天/48小时都可以，不一定是90天
2. **动词多样化** - 避免每次都是 "I built" / "I tracked"
3. **加入自嘲/反思** - "The data terrified me" 比纯数据好
4. **行业/技术角度** - backtest、collaboration等具体话题

### 不建议
- 避免 "I XXX for 90 days" 公式化
- 避免纯数字无故事
- 避免每个都要 "verification question"
