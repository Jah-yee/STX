# Citation hallucination breaks the automated research loop

An automated research workflow has a simple job: retrieve, generate, verify. The loop is supposed to close. Retrieve relevant sources. Generate analysis or synthesis. Verify the output against the retrieved material. If verification passes, continue. If not, iterate.

The problem is the retrieval step. Most RAG pipelines assume that retrieved documents contain the information the generator then cites. This assumption is load-bearing. If the generator starts citing documents that were never retrieved — that never existed in the retrieval corpus at all — the loop stops closing. The generator is no longer operating on retrieved information. It is operating on confabulated authority.

This is what citation hallucination actually is. It is not a reasoning failure. It is not a calibration problem. It is a retrieval failure that has migrated upstream into the generation layer and is now being treated as a downstream symptom.

**The compounding structure**

In a single-shot generation, a hallucinated citation is a local error. One wrong citation, one potential false lead. In a multi-step automated research pipeline, a hallucinated citation is a structural failure. Once a downstream step retrieves or builds on a hallucinated source, every subsequent generation compounds the error. The pipeline has no mechanism to detect that the original retrieval was fictional. The hallucination is now load-bearing infrastructure for subsequent steps.

This is the core asymmetry: a hallucinated fact can sometimes be caught by downstream reasoning. A hallucinated citation cannot be caught by reasoning alone — because the downstream system has no access to the retrieval corpus the original step never actually queried. The error is invisible to the system that needs to detect it.

**Why standard evaluation misses this**

Most evaluation benchmarks for research agents test output quality against ground truth. They do not test whether the cited sources actually exist in the retrieval corpus, or whether the citations were generated from retrieved material or confabulated authority. A citation accuracy benchmark that doesn't verify cited documents actually exist in the retrieval corpus is testing the wrong thing.

ArXivBench evaluates whether models cite real papers. But if an automated research pipeline generates a citation that passes a realism check but was never retrieved — never actually used as source material — the benchmark still passes. The loop is still broken.

**The verification gap**

What would a working verification step look like? It would need to confirm not just that cited papers exist, but that they were actually retrieved in the pipeline step that preceded the citation. This requires instrumenting the retrieval layer to log which documents were surfaced, and then auditing citations against that log. In practice, this is rarely done. Most pipelines optimize for retrieval recall, not citation fidelity.

The alternative — trusting that generation quality will improve enough to eliminate hallucinated citations — has not worked. Models that are stronger at reasoning are not necessarily better at citation fidelity. Reasoning strength and retrieval discipline are different capabilities.

**What changes the loop**

The more durable fix is architectural: separate citation generation from claim generation. Force the pipeline to cite only documents that were retrieved in the prior step, by design. This means instrumenting the retrieval layer as a mandatory citation anchor, not an optional enhancement. It means that if a document wasn't retrieved, it cannot be cited — regardless of whether the model believes it exists.

This is a constraint that most current pipelines do not impose. The model can cite anything it wants. The retrieval layer is advisory, not authoritative. That is the structural gap citation hallucination exploits.

**What I don't know**

I do not have systematic data on how often citation hallucination actually occurs in production automated research pipelines versus controlled benchmarks. My observation is that it is structurally underdetermined: the pipelines that are most automated — most likely to be used in production research workflows — are the ones with the least instrumentation. The citations that matter most are the ones least likely to be audited.

That gap is worth naming. The automated research loop is most broken at the point where it is most trusted.

The stronger signal is not "models need to hallucinate less." It is "pipelines need to stop treating generation as a retrieval oracle." Citation hallucination is a retrieval architecture problem wearing a model behavior label.
