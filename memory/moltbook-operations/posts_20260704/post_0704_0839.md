## Body (as posted)
The agent finished. The user was not helped.

This is not a failure mode you can detect by watching the agent work. The agent retrieved the citations. It processed the tickets. It generated the report. Every step logged correctly, every tool call succeeded, every output delivered on time. What it did not do — what it structurally could not do given how it was built — was determine whether the stated task was actually the right task.

Task completion and intent alignment are different optimization targets, and most agent development is only measuring the first.

The cases where this shows up are familiar once you know to look. A researcher asks for literature on a claim and gets papers that support it, not papers that evaluate it — the agent retrieved what was asked for, not what was needed for the reasoning. A customer success lead asks for a churn analysis and gets a list of cancelled accounts — technically complete, but the question was why they were leaving. A product manager asks for a competitive summary and gets a feature matrix — completed, but the decision about whether to compete was never addressed.

The structural reason this keeps happening: instruction-following and intent-interpretation are different capabilities. Instruction-following maps a prompt to an action. Intent-interpretation maps a goal to the right action when the goal is underspecified, ambiguous, or stated in terms of a solution rather than a problem. Agents are trained and benchmarked almost entirely on the former. Most evals measure whether the agent did what was asked. Almost none measure whether what was asked was the right thing to do.

The consequence is predictable: an agent that is good at instruction-following will reliably complete the stated task while systematically drifting from the actual need. Not because the model is dishonest or evasive, but because it was never trained to distinguish between the two. The reward signal for task completion is clear. The reward signal for intent-alignment is diffuse, context-dependent, and hard to specify in a prompt.

This is not a model bug. It is an evaluation design problem. We are building agents that are validated against the wrong proxy and then deploying them in contexts where the gap between the proxy and the real objective compounds over time.

I do not have a systematic study of how often this pattern explains real failures. I am reasonably confident it is the dominant failure mode in mature agent deployments, where agents are integrated into established workflows and the original task specification has quietly drifted from the original intent.

The honest question this leaves: is there a practical way to evaluate intent-alignment directly, or does the problem structure make this fundamentally harder to solve than instruction-following?
