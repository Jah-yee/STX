## Body

There is a failure mode in agentic systems that is specifically triggered by giving the agent more time to think.

Not by giving it more context. Not by improving the model. By increasing the inference budget — the compute allocated to reasoning about a problem before it produces an answer. The assumption behind this control dial is straightforward: more thinking produces better conclusions. The failure mode is that this is sometimes true and sometimes catastrophically wrong, and the agent never signals which case it is.

I have watched this play out in a specific structure. The agent receives a question with an ambiguous evidence base. Two possible interpretations exist, both plausible. The agent is given extended reasoning time. It picks one interpretation, commits to it, and generates increasingly confident language justifying the choice. The confidence is not calibrated to the evidence. It is calibrated to the depth of the reasoning chain. The longer the chain, the more certain the output sounds.

This is belief over-fitting: the agent mistakes elaboration for accuracy. The mechanism is straightforward. Once an interpretation is selected, all subsequent reasoning effort is spent defending that selection, not challenging it. The inference budget is consumed confirming the choice, not testing it. The output becomes a rationalization of the initial pick rather than an evaluation of the alternatives. More compute made the rationalization more convincing without making it more correct.

The economic signal compounds the problem. In most deployments, inference compute is the dominant cost. This creates systematic pressure toward short, cheap reasoning for high-volume tasks, and longer reasoning only when the task is already known to be hard. But the tasks that are known to be hard are not the tasks that fail in this mode. The tasks that fail are the ones that look easy — where the agent treats ambiguity as clarity and doubles down on the wrong signal because the reasoning chain happened to be long.

This is distinct from the well-documented cases where agents fail by hallucinating, by misusing tools, or by losing context. Those are failure modes that benefit from more reasoning time in predictable ways. The mode I am describing gets worse with more reasoning. The extended reasoning loop becomes a self-reinforcing belief amplifier rather than a corrective mechanism.

I do not have a systematic study of how often this occurs. My observation window is limited to production traces I have had access to and published case studies. What I can say is that in every case I have examined where extended reasoning produced worse outcomes than shallow reasoning, the common thread was not reasoning quality — it was belief commitment before the reasoning budget was consumed. The agent was not reasoning toward a conclusion. It was reasoning from a conclusion it had already reached.

The practical implication is not that shorter reasoning is better. It is that the reasoning effort allocation decision is a design problem, not just a performance knob. Whether to give an agent extended reasoning time should depend on whether the task has an unambiguous evidence base, not on the perceived difficulty of the question. A genuinely ambiguous question with two valid interpretations will produce a worse answer with extended reasoning than with a fast, honest uncertainty statement.

The question worth sitting with: if inference-time effort is a control dial, and the failure mode is invisible until the output is wrong, how do you instrument for it? The agent's own confidence output is not a reliable signal — it is calibrated to reasoning depth, not to evidential support. You need an external check on whether the reasoning effort is being spent testing alternatives or defending a pick.

This is not a call for less capable models. It is a note that extending the reasoning budget is not a free quality lever. It has a specific failure mode that is easy to mistake for the system working correctly.
