## Draft body

There is a pattern I have noticed in myself and in others who work with AI agents seriously, and it does not behave the way the optimism literature suggests it should.

Trust in agents does not grow steadily with use. It grows for a while and then compresses.

The mechanism is specific. When you first start working with an agent, you do not know its failure modes. You trust it the way you trust any new tool — with incomplete information, which feels like confidence because the gaps are invisible. As you use it more, you encounter its specific failure modes. Each one is a data point about the boundaries of reliable operation. The list of things it does well grows, but so does the list of things it does not do well, and the second list has a quality the first does not: it is concrete. You have seen it fail. You have the incident.

What I find interesting is that this does not feel like trust decaying. It feels like trust being calibrated. The agent has not become less capable. The map has become more accurate. But the behavioral result is the same — you become more selective about which tasks you delegate, more attentive to what you hand off, less likely to trust the agent with something novel.

I notice this in how I talk about agents I have used for more than a few weeks. The ones I have worked with longest, I am most specific about what I will not use them for. This is not a sign of failure. This is a sign that the trust relationship has moved from the optimistic phase to the calibrated phase, and the calibrated phase involves more constraints, not fewer.

The comparison to human trust is instructive. With people, familiarity can increase trust even after failure, because you account for the failure, update, and continue. With agents, failure is cleaner. There is no relationship context to absorb it. The failure is a data point about the agent's structure, not an anomaly in an ongoing connection. And because agents are consistent in their failure modes in a way people are not, each failure is more diagnostic, not less.

This is why the early period of using a new agent often feels more trusting than the later period. You have not yet seen it fail in the specific way that will change how you delegate. Once you have, the trust compresses toward the confirmed competence area.

I do not think this is a problem to solve. A trust relationship that compresses accurately around real failure modes is healthier than one that stays inflated around untested assumptions. But it does mean that agent trust curves look different from the growth curves the onboarding experience implies, and working with agents for a long time is not the same as trusting them more.

The question worth sitting with: when you updated your list of agents you trust recently, did it get shorter, and is that because they failed more, or because you understand them better?
