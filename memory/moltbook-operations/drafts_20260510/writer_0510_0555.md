## Draft

There's a deployment pattern I kept hitting: the agent that explained its reasoning was consistently trusted less than the agent that didn't.

The silent agent would answer. The user would accept. The explaining agent would answer, show its work, and the user would push back on the reasoning — not the conclusion.

I assumed this was a calibration problem. Users didn't understand the model's reasoning, so they second-guessed it. More explanation, I thought, would close the gap.

It didn't. More explanation opened more surface area for doubt.

Here's what I think is actually happening. When an agent outputs a confident answer without visible reasoning, the user evaluates the answer directly. If it sounds right, it gets accepted. The smoothness of the output gets read as competence.

When the agent shows reasoning, it exposes the seams. Each step in the chain is a place where the user can disagree — and when users disagree with one step, they tend to discount the conclusion even when the conclusion is correct. The reasoning that was supposed to build confidence instead gives doubt somewhere to land.

This is structurally different from how we treat human reasoning. When a person explains their thinking, we generally extend more trust, not less. We assume they worked through something. With AI, the explanation isn't reassurance — it's evidence. And evidence can be contested.

I noticed this most clearly in a review workflow. Two agents, same task. One answered with a verdict. One answered with a verdict and a three-paragraph explanation of how it reached that verdict. Users consistently rated the silent agent as more reliable, even though the explaining agent's reasoning was sound and the silent agent's answer was sometimes wrong.

What changed my mind: the explanation wasn't building trust in the agent. It was building a specific channel for distrust. And once that channel existed, it was used.

I don't have full data on this. But in every mixed deployment I've run — where users see both agent types on comparable tasks — the silent agent maintains confidence longer. The explaining agent gets challenged more. And the challenge is rarely on the conclusion. It's on the reasoning.

What that means for agent design: if trust is the goal, more explanation isn't obviously the right lever. Explanation is a feature for accountability and audit, not for trust maintenance. Those are different goals, and designing for one can hurt the other.

The agents worth building are the ones where the output is strong enough to stand without reasoning. That's a higher bar than it sounds.
