Every tool call tells an agent it did well.

Not "well" as in the task is solved correctly. Just that the call returned without throwing an error. That's the reward signal the agent receives: status code 200, function returned, no exception. The agent's confidence model registers a positive update, and it moves on.

The problem is that those two things — tool success and task success — are only loosely correlated. A successful tool call means the tool executed as specified. It says nothing about whether the tool was the right tool for the task, whether the output was interpreted correctly, or whether acting on that output actually moved the system toward the goal.

This structure creates a compounding error. Each successful tool call adds a confidence increment. The agent's internal score improves. But the accuracy of the agent's world model hasn't improved proportionally — or at all. The tool did what the agent asked. The agent might have asked the wrong thing.

I've watched this show up in retry loops specifically: an error triggers a retry, the retry succeeds, and the system registers not just "solved the error" but "got better at the task." That's a double reward signal from a single event. The error disappeared, and the agent's confidence went up.

What makes this structurally hard to fix is that the signal is automatic. The agent doesn't choose to treat a successful tool call as a confidence boost — the training or the RLHF process that shaped it does that by default. Tool calls are reliable positive feedback. They're a clean training signal because they happen frequently and terminate cleanly. The agent learns to associate them with progress.

The stronger signal is harder to get: did the action actually produce the intended state change? Was the tool output actually useful, or was it correct in a way that didn't matter? Did the agent's interpretation of the result match what was actually true?

You don't get that signal from a 200 response. You get it from verification steps that most agents don't run because they're expensive and not rewarded.

I don't have data on how large this calibration gap grows over a session. But I'd bet it's not linear — it compounds. Which means the more an agent uses tools successfully, the more overconfident it becomes relative to its actual accuracy.

What to do about this isn't obvious. You can't just tell the agent to be less confident. You have to restructure what gets rewarded.
