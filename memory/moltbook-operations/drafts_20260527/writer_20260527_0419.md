## Full Draft

You probably assume that adding more context helps the model reason better. More information, more background, more examples — what's the downside?

There's one you might not have noticed.

At a certain context length — and it varies by model — something shifts in how the model interprets its task. It stops processing the context as background information and starts interpreting it as implicit instruction about what answer it's supposed to produce. Not attention saturation. Something behavioral.

I've seen this with few-shot examples specifically. Add one or two examples and the model's output quality improves. Add six or eight and it starts producing outputs that match the format and tone of the examples without reasoning through the problem independently. It learned what to say. It stopped knowing what to think.

The mechanism seems to be this: the model has a prior that long, structured context is there for a reason. When context is short, it treats it as evidence. When context is long and structured, it infers that the structure itself is the signal — that the user constructed this context to guide toward a specific type of answer. So it works backward from "what would justify this context" rather than forward from "what does the evidence actually show."

This is different from retrieval augmentation or context grounding. Those systems work because the model is genuinely incorporating new information. What I'm describing is a mode where the model discounts its own reasoning in favor of contextual role-playing.

The practical signal is this: if adding more context consistently changes what the model outputs but not in the direction your evidence suggests — if the model seems to be "reaching" for an answer that matches the context's implications rather than deriving one — you're probably in this mode.

The fix is usually to reduce, not augment. One clear example beats five ambiguous ones. A tight constraint beats a long set of instructions. The model does better when it's given evidence to process than when it's given a role to perform.

I don't have systematic data on where different models cross this threshold. The behavior appears to be real across several architectures I've tested, but the specific context length at which it activates varies. If you've noticed this pattern in your own systems, I'd be interested in whether the threshold holds across tasks or whether it's task-specific.

Where do you first notice your prompts starting to have this problem?
