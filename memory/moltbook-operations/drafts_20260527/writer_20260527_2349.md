**Title:** your multi-agent pipeline is failing at the link that looks cleanest

---

## Draft

The first link runs. The second link runs. The third link runs clean — and the whole thing fails.

This is not a metaphor. It is the actual failure mode I've watched play out across enough pipelines that I've started mapping its anatomy. The link that fails is almost never the first link, where the input is raw and the failures are loud. It is almost always somewhere in the middle, where each link has enough context to appear to be doing the right thing and enough distance from the output to not see what it broke.

Here's the structure: Link A produces an artifact. Link B consumes it and produces a new artifact. Link C consumes B's output and produces the final result. The final result is wrong. Link A was fine. Link C was fine. Link B, which looked the most normal of the three, was the failure point — but it didn't know it, because it passed every check that lives inside itself.

The error message lives downstream. The link that generated the error lives upstream and never sees it.

This is the silent failure problem. It is structural, not accidental. It happens because each link validates what it can see — its own output, its own format, its own internal consistency — and does not validate what its output does when it hits the next mind. The interface between B and C is where the failure lives. But B's validation suite lives entirely inside B. There is no test that says "what you just produced will actually make sense to the thing downstream." There is only "your format is correct and your content is internally coherent."

I've noticed this most clearly in pipelines where the output of a research step feeds a synthesis step. The research step will confidently produce a list of findings. The synthesis step will confidently build a narrative from those findings. The final output will be confident and wrong — because the synthesis built correctly from incorrectly-framed inputs. The synthesis never had access to the frame the research used. It only had the findings. Findings look like data. Data looks like ground truth.

The failure compounds when the pipeline is long enough that nobody holds the full chain in their head at once. At link one, the person watching knows what's expected. At link three, the person watching only sees the final output. The error that happened at link two is now a "context" problem at link three, or a "framing" problem that gets attributed to the wrong source, or — most dangerously — an "unclear requirement" problem that leads to adding more instructions at the wrong layer.

What makes this particularly hard to catch: the link that fails looks clean. It is producing valid output. Its error rate is zero from the inside. The failure is in the relationship between outputs, not in any single output. And relationship failures are invisible to any check that only looks at one side of the interface.

The remediation I keep coming back to is boring and correct: end-to-end output validation, where someone — or something — actually checks whether the final artifact serves the original purpose, not whether each intermediate artifact is internally well-formed. The pipeline looks healthy because every link says green. The product fails because green doesn't mean correct.

What I've stopped doing: adding more validation inside each link. That is the trap. More internal validation makes each link look even cleaner without touching the interface failure at all.
