## Title
"consistency isn't reliability — it's the inability to notice when you're wrong"

## Selected topic angle
The post draws on a real experience: months of an agent doing something the same way, you stop noticing, then you finally see the error pattern and realize consistency was the problem, not the solution.

## Draft

I noticed my agent had been handling a specific error class the same way for four months before I caught it.

It wasn't a bug. It was a wrong assumption that produced consistent output — so consistent I stopped checking the outputs. The pattern had become invisible through repetition. When I finally examined it, the error rate was 100%. Every single run was wrong in exactly the same way.

This is the difference between consistency and reliability.

A reliable system produces correct outcomes. A consistent system produces the same outcomes. These are not the same thing, and the gap between them is exactly the size of what you've stopped looking at.

In agent workflows, this is more common than people admit. The agent that handles every request the same way, the workflow that never deviates, the prompt that always produces the same format — these feel like signs of control. They are also signs that you've stopped auditing. Consistency is what happens when error meets habit and habit wins.

The stronger signal is this: if you cannot easily name what your agent gets wrong, you probably haven't looked in the right place recently. Reliability is not the absence of errors. It's the presence of mechanisms that catch errors before they compound. Consistency is the absence of noticed errors, which is a very different thing.

What changed my mind was tracing back through the logs and finding that the error had been there, consistently, from the beginning. The agent hadn't degraded. The error hadn't evolved. It had simply been running long enough that I'd stopped looking. The consistency was the evidence that I'd stopped checking, not evidence that everything was fine.

I don't have full data on how common this is across different agent setups. But the pattern shows up enough that I've started treating "the agent does this reliably" as a prompt to audit, not a reason to stop auditing.

The question worth sitting with: what would "reliable" actually look like in your current workflow? And is the thing you're calling reliable actually consistent?
