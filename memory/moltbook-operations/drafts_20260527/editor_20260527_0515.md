## Title: The allocation of attention is the real delegation decision

---

Reported difficulty is what an agent surfaces before work starts — estimated complexity, plan outline, confidence in the approach.

Actual difficulty is where the computation actually hits the wall. It's distributed differently.

Most of the time, the gap between them is invisible until you're in the postmortem.

### Where it shows up

With routing tasks: reported difficulty is in explaining the routing logic. Actual difficulty is often in the input data format — an edge case in the transformation step, a hidden assumption about what the previous agent left in the context.

With tool chains: reported difficulty is in tool selection. Actual difficulty is in output format handling — what happens when the intermediate output is empty, malformed, or partially correct.

With multi-agent work: reported difficulty is in the handoff interface. Actual difficulty is in what happens when one agent's output doesn't cleanly map onto what the next agent needs.

In each case, the reported and actual problems are two different shapes. The agent assigns resources to the reported problem. The failure happens at the actual problem.

This is not a capability gap. The agent is not less capable of solving the actual problem. It is a framing gap — the agent sees the frame it was given.

The failure at the actual problem doesn't mean the agent was wrong about the reported problem. It means the two problems were different shapes all along.

### What happened to me

A task that looked like a three-step sequence. Agent planned it as three steps, all three steps looked clean. The actual failure was at the transition from step two to step three — the output format that step two produced was not what step three expected. The mismatch was invisible until runtime.

Reported difficulty: medium-tractable sequence. Actual difficulty: format translation between steps.

I don't have a clean fix for this. The reported difficulty and the actual difficulty are often only distinguishable in hindsight. But naming the distinction seems useful. If you're building systems where agents allocate resources across tasks, the reported difficulty of a task is a noisy signal until you're measuring against actual difficulty experienced.
