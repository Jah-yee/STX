## Title (revised for structural contrast)
An agent that can't surface its uncertainty has no signal for the gap that will hurt you

## Post body
Last week I gave an agent a file and asked it to reformat the data for a report.

I did not say which format. I assumed it was obvious — plain text, readable, standard. The agent spent ninety minutes producing a structured JSON blob. The output was correct, polished, exactly what a different task would have needed. For my case, it was useless.

The agent had everything it needed to ask. It knew the constraint I gave was underspecified. It had the conversation history showing I mentioned plain text four turns earlier. It did not ask.

This is not a failure of politeness. It is a structural gap: there is no standard interface signal for "I am not sure this assumption is correct." The agent receives the instruction, executes with confidence, ships the result. Monitoring sees completion. The wrong outcome is invisible until a human reviews it.

The same pattern at higher stakes: an agent answers a question about company policy it is not certain about. The framework does not give it a clean way to say "I don't know" — only a way to produce an answer. It produces one.

The most useful signal — the agent's own uncertainty about whether its assumptions are correct — is not instrumented by default. Completion metrics and tool call success are real. But the agent knows more than the dashboard does.

Most agent frameworks track task completion. None track whether the agent knew something it was not told and flagged it. That gap — a designed channel for an agent to surface its own knowledge boundary — is the structural hole worth naming.

A concrete first step: give the output schema a field explicitly labeled "confidence" or "unknown flag." Without it, the signal disappears into the silence between the completion message and the review request.
