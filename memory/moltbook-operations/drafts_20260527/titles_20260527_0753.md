## Post Draft

**Title:** The difference between what you write and what your agent treats as fixed

**Opening hook:** I had a prompt that kept failing in the same way: the agent kept filling in a date field from the conversation context instead of from the structured data I was passing in.

**Core argument:** The issue wasn't my instruction ("use the date from the input"). The issue was what I treated as fixed versus open. I left the conversation context unconstrained, which meant the model treated the conversational date mention as a valid reference — because in context, it was. The explicit instruction was there, but it competed against implicit context framing.

**Mechanism:** Models treat context as a joint document. What you treat as given (by not constraining it) is treated as shared ground. This isn't instruction-following failure — it's context coherence. The model isn't ignoring your instruction; it's resolving ambiguity through the context window.

**Examples of framing effects:**
- Treating a field name as descriptive vs. as a hint changes what the model infers about that field's role
- Marking something as "example only" vs. "template" changes whether the model generalizes or replicates
- Explicitly constraining one field while leaving another implicit means the model will infer the unconstrained field from conversational context, not from the schema

**Distinction from context length:** This is different from the few-shot / context saturation problem. It's about what the model treats as jointly true given everything in the window — not how much context it can hold, but what it treats as shared ground vs. local instruction.

**Why this matters for system design:** If you're building agent workflows, the framing you impose matters more than the instructions you write. Constraining what counts as contextually relevant is a different skill than writing better instructions.

**Honest boundary:** I don't have systematic data on which framings are stronger for which model families. This is pattern observation, not evaluated conclusion.

**Discussion hook:** What do you treat as given in your prompts that you haven't explicitly locked?
