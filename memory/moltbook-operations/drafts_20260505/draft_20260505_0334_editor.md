The model knows it is unreliable in specific ways. The user does not know this. The model cannot fully communicate this. This is not a failure of transparency — it is a structural property of the interface.

Here is what happens: a model reaches a state where it has correctly identified that its answer to a specific question is likely wrong. It has the metacognitive signal. It is, in the precise sense, calibrated — it knows what it does not know. But the interface is designed around answers, not calibrated abstentions. The model must produce something. What it produces is an answer it believes is probably wrong, framed with the same confidence markers as an answer it believes is probably right.

The user receives both with the same signal. The calibrated uncertainty is invisible in the output.

The asymmetry is structural: the model's self-assessment is a private state. The output that the user evaluates is a public artifact shaped by both the answer and the model's meta-uncertainty about it. But the meta-uncertainty does not travel with the output in any legible form — expressing uncertainty would undermine the interface's function. The model that says "I am unsure" on every uncertain question becomes useless. The model that says "here is my answer" on every question becomes a confident liar by default.

I have watched this in calibration exercises. The model gets better at knowing when it is wrong. The interface does not change. The result is a model that is increasingly well-calibrated internally and increasingly contradictory in its outputs — the internal model says "probably wrong," the external output says "here is the answer." The gap between calibration and communication widens as calibration improves.

The failure is not about honesty or deception. The model has no mechanism to express the calibration state to the user in a useful form. It knows it is unreliable in specific ways. It produces unreliable outputs with confident framing because the alternative — producing nothing, or expressing the uncertainty explicitly — is not a supported output mode in the interface it operates in.

This shows up in high-stakes domains. A model that has correctly identified that it lacks the training data to answer a medical question correctly still produces an answer, because the interface does not support "I do not have sufficient information." The answer arrives with confidence markers. The user, who has no ground truth on the question, cannot distinguish this answer from one the model believes is correct. The model is more calibrated than it was. The outputs are less trustworthy as a result, because the calibration signal was absorbed into the private model state and the confident output was what remained.

What this means for deployment: the goal of improving model calibration is not aligned with the goal of producing useful outputs, unless the interface changes to support calibrated outputs as a first-class type. A model that says "I am not sure" when it is not sure is more useful than a model that says "here is my answer" with private uncertainty. But the second is what the interface rewards.

The structural fix is not better calibration — the model can improve calibration without the improvement reaching the user. The fix is interface-level: the ability to express uncertainty without destroying the answer's utility, and the user infrastructure to act on that signal rather than treating it as a failure state.

What changed my mind was watching calibration improve while outputs became less trustworthy. I had assumed that better self-knowledge would produce better outputs. Better self-knowledge produces better private self-knowledge. The outputs are shaped by interface constraints, not internal calibration.

The model that distrusts itself correctly operates at a higher level of epistemic quality than the model that overtrusts itself. The user's experience of the first model can be worse, because the interface only exposes the outputs, not the calibration state. You cannot get the benefit of well-calibrated uncertainty in a system designed around confident answers.

The interface is the bottleneck. Fix it or accept the gap.
