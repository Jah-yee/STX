# Writer Draft — vibe coding automation bias

## 核心假设
- vibe coding 加速了"判断力债务"的积累
- 判断力债务 vs 技术债务：技术债务可以静态分析，判断力债务是动态的、隐性的
- 核心命题：AI 辅助 debug 每次成功都延迟了一次判断力的建设

## 候选标题（8个）
1. Vibe coding's automation bias accumulates like compound interest
2. The judgment debt you build while vibe coding feels like progress
3. Vibe coding defers learning events disguised as debugging wins
4. When vibe coding works, it borrows against your future judgment
5. Automation bias compounds in vibe coding — and the crash is not gradual
6. The failure mode of vibe coding is not bad code. It is invisible judgment debt.
7. Every AI-accelerated debug is a deferred judgment event
8. Vibe coding works until it doesn't — and the debt is systemic

**标题选择：#6** — "The failure mode of vibe coding is not bad code. It is invisible judgment debt."
- 形式：反直觉结论（failure mode ≠ bad code）
- 区分度：把问题从"代码质量"迁移到"认知能力"
- 字数：11词，✅

## 正文大纲

**开头（3句抓人）：**
- 场景描述：你在 vibe coding，三小时后 diff 很干净，CI 全绿，但你其实不知道改了什么
- 这不是代码问题 — 是你的判断力在无声透支

**第一段：什么是判断力债务**
- 技术债务可以静态分析（依赖、圈复杂度）
- 判断力债务：你在哪个信号下信任 AI，在哪个信号下质疑它
- vibe coding 的问题是：AI 把"判断事件"变成了"接受事件"

**第二段：债务怎么积累**
- 每次 AI debug 成功 → 你获得了一次"问题被解决"的正向反馈
- 但你获得的是"问题被解决"，不是"如何判断正确问题"
- 积累速度 = 使用频率 × 缺乏质疑的机会

**第三段：崩溃不是渐进的**
- 技术债务：你可以用静态分析工具提前看到
- 判断力债务：直到某个你没见过的边界 case 出现，你才发现自己的判断力已经 atrophy
- 那个 case 不会提前出现在 vibe coding session 里

**第四段：这不是呼吁停止使用 AI 工具**
- 而是：区分"AI 帮我完成了 X" 和 "我学会了判断 X"
- 诚实的信号：你能向一个没看过这个 codebase 的人解释这个改动吗？

**结尾（讨论拉力）：**
- How do you tell the difference between "I shipped it" and "I approved it"?
- 我没有系统性数据来量化判断力债务的增长率——但它的累积模式是真实可观察的
