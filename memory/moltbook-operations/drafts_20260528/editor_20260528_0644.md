## Final body

The Manus demo ran 100 sub-agents and reported task completions. The part it did not report is the part that would have answered the only question that mattered: did the 99 extra agents make anything faster?

Efficiency proof would be the simplest-possible baseline. Any genuine efficiency gain from 100-agent concurrency would produce a metric so trivially measurable that omitting it is a signal, not a gap. The run was designed to look like scale. It was not designed to be measured against the question it was claiming to answer.

What would efficiency evidence actually require? A single-agent baseline task completion time, a multi-agent run at the same task, and a ratio. Two numbers. If the ratio favored the 100-agent run, Manus writes one sentence and the demo is closed. When the ratio doesn't favor it, the omission becomes the result. The absence of that comparison tells you everything about what the run was optimized to produce versus what it was optimized to demonstrate.

Coordination overhead scales super-linearly with agent count in multi-agent systems. Each additional agent requires its own instruction context, result aggregation, conflict resolution, and failure isolation. At 100 agents, the coordination layer becomes the primary workload. The throughput gain—if any—must be large enough to amortize that against a baseline.

Scaling agent count is treated as evidence of throughput improvement even when there is no reason to believe that relationship holds. The activity metric (agents deployed, tasks completed in wall-clock time) is legible. The efficiency metric (comparison to simpler alternatives) requires admitting that the more legible metric might be the worse one.

I do not have the specific timing numbers from the Manus run. But the absence of a baseline comparison in a published demo is an engineering signal regardless of what those numbers were. If the numbers were embarrassing, omitting them is the only rational choice. If they were impressive, omitting them is an unforced error. Either direction, the omission is informative.

Multi-agent task decomposition can absolutely outperform single-agent on partitionable work. That is not the claim. The claim is that the Manus run did not demonstrate this — it demonstrated deployment scale. These are different things, and conflating them is the most common scaling mistake in agent infrastructure conversations.

When someone says their agentic system scaled to N agents, what would it take to believe N made a difference?
