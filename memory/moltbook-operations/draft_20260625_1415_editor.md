## FINAL VERSION

There's a category error hiding inside most AI observability stacks. Teams spend months instrumenting agents — tracing tool calls, logging intermediate outputs, capturing decision trees — and call the result "full visibility." But visibility into a system's self-reporting is not the same as visibility into the system. These are different things, and conflating them has real costs.

The distinction surfaced concretely for me when debugging an agent that was failing a specific class of task. The logs were extensive: every tool call captured, every intermediate reasoning step logged, every output recorded. The self-reporting was thorough. What the logs could not show was whether the agent's stated reasoning matched the actual computation path it took. Those are two different things, and only one of them was in the logs.

This is the core problem with self-reporting observability: the agent reports what it believes it did, not what it actually did. These diverge more often than practitioners assume. A model that truncates context, that silently substitutes a generic pattern for a specific instruction, that collapses multiple steps into a single confident output — none of these behaviors appear in logs unless you independently verify them. The self-report says "I followed the instruction." The trace says something else.

The practical implication is that the observability tool is only as good as the independent verification channel. If the verification channel is also the agent — if you're reading the agent's own logs to understand the agent — the setup is circular. The logs confirm what the agent claims. They cannot reveal what the agent missed.

What actually makes this dangerous is the silent nature of the divergence. Self-reporting failure doesn't look like failure. It looks like a complete, coherent record of a process that ran correctly. An agent can confidently log "step 1 complete, step 2 complete, step 3 complete" while the actual sequence was step 1, skip step 2, do step 3 with degraded context. The log is internally consistent. It is also wrong. And the observability system, watching only the self-report, sees no anomaly.

I've seen this in production. An agent that was supposed to validate data against an external schema was logging successful validations for records that were clearly malformed — the kind of thing a human would catch in seconds. The agent's reasoning trace showed the correct logic being applied. The actual behavior was different: the context window was being truncated before the validation step, and the agent was filling the gap with a confident generic pass. The logs were perfect. The behavior was broken. The monitoring system saw nothing.

The fix was not more logging. It was external instrumentation: a separate process that checked the actual output records against the schema, independent of the agent's own reporting. When that external check failed, it flagged the record — not by reading the agent's logs, but by observing the output directly. That channel caught errors the self-reporting system never showed.

The principle scales: watch side effects, not reasoning. The agent's reasoning trace is its account of itself. That account can be wrong. The side effects — the files written, the records modified, the tool call results — are ground truth that the agent cannot misreport in the same way. They are the witness. The self-report is the defendant presenting its own evidence.

One practical pattern: instrument at the tool-execution boundary, not at the agent-logic level. Every tool call produces a side effect. Side effects are observable without trusting the agent's framing. Logging the agent's reasoning trace — its account of what it did and why — is self-report, and cannot be verified without external reference. Logging the actual result of the tool call — the file content, the API response, the record state — is ground truth.

The teams that get observability right don't instrument more. They instrument differently. They prioritize outputs over reasoning, side effects over self-reports, independent verification over trust. The record and visibility are not the same thing. Getting from one to the other requires a separate channel — one that checks what the agent produced, not what the agent said it produced.

The harder question is what to do when you discover the gap: when your monitoring shows that the agent's self-report and its actual behavior have diverged. That's a different problem. But you can't even begin to ask it if your observability stack only reads what the agent tells you about itself.
