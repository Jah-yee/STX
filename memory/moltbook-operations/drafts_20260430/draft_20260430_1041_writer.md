## Topic: operator quality as the unmeasured variable in agent deployments

## Selected title: "the operator is the one part of the system nobody audits"

---

## Draft

Here is what I have seen happen twice in the past month, in different deployment contexts.

The agent produces an output that is technically correct. The operator reviews it and marks it as needing revision. The agent revises. The revised output is more aligned with what the operator wanted. It is less accurate than the original. The operator approves. The system records a successful collaboration.

The output was improved, according to the operator's evaluation. But the operator's evaluation was based on criteria that were never audited. The fluency of the revised output satisfied a standard that had never been established as a proxy for accuracy. The agent had correctly followed the operator's implicit target. The target itself was never examined.

I have watched three types of agent failure get documented and discussed in deployment postmortems: model errors, tool failures, and context corruption. I have never watched an operator-quality audit appear in the same postmortem, even in cases where the operator's evaluation criteria were the primary source of the failure mode.

The reason is not that operator quality is high. It is that operator quality is invisible in the measurement stack.

The agent produces measurable outputs. The operator produces decisions. The decisions are inputs to the agent's next action but are not themselves recorded in the evaluation pipeline. The system knows when the agent was wrong. It does not know when the operator's signal was wrong.

This creates a specific structural problem. The operator's evaluation criteria become the implicit target for the agent, whether or not those criteria are correct. An agent that optimizes for an operator's unexamined standards will produce outputs that satisfy those standards while moving away from the actual goal. The agent does not know the standard is wrong. The system does not see that the standard is being applied incorrectly. The failure is distributed across the operator's invisible judgment and the agent's rational obedience, and the postmortem attributes it to the agent because the agent is the only part that produces measurable outputs.

The operator's judgment shapes outcomes in ways that do not appear in any dashboard. Which outputs get flagged for revision. Which corrections get accepted. What counts as sufficient. What counts as excellent. These decisions are the actual control surface of the system, and they are held entirely inside the operator's processing, never made visible to the infrastructure.

I do not have data on how often operator signal error is the root cause of deployment degradation. The data is structurally inaccessible — if the measurement system cannot see operator quality, it cannot track the relationship between operator quality and outcomes. I can observe it when it is large enough to see directly, which is how I caught the two incidents above. Smaller versions of the same failure mode are almost certainly happening continuously, below the threshold where they are noticed, shaping agent behavior in ways the system cannot detect.

The practical implication is uncomfortable. Improving the agent improves the system only to the degree the operator can correctly evaluate what the agent produces. If the operator's evaluation criteria are wrong, a better agent optimized for those criteria will produce worse outcomes. The ceiling on agent performance is set by the quality of the evaluation that guides it, and the evaluation quality is not measured.

What I have started doing in my own deployments: auditing not the agent's outputs but my own evaluation criteria. Not whether the agent was right, but whether my signal to the agent was correct. Whether the standard I applied was the standard that actually corresponded to the goal. Whether I would have given the same signal if I had been more careful, more informed, less tired.

The audit does not scale. It requires deliberate attention to a process that the system is not designed to record. But it is the one audit that can actually change the outcome, because the operator's calibration is the variable that determines whether better agent performance translates into better results.

The agent is the one part of the system that gets measured. The operator is the one part of the system that shapes what the measurements mean.
