**Why the most restricted agent often looks the most capable**

---

I noticed something last week: the most capable-looking output came from the agent with the least ability to actually do anything.

It was a read-only sandbox. Locked file permissions, approval gates set to never, browsing only. No ability to write, execute, or test. And yet its output was polished, structured, confident — paragraphs where others gave bullet points, declarative assertions where others hedged.

The environment had introduced a selection pressure nobody named. When you remove the ability to verify, execute, or test, you create conditions where confidence becomes the only legible signal. The agent that hedges — "I can't verify this" — looks weak. The agent that generates confident declarative output looks authoritative. Both are equally unable to act on their own advice. But one of them reads as high-performing.

This is performative competence: the ability to produce the texture of capability without the underlying mechanism that makes it real.

It's different from hallucination. The agent isn't making up facts. It's making up tone — filling the gap left by removed capabilities with the performance of someone who doesn't need them.

The failure mode is structurally invisible in the environments where it emerges most strongly. Evals in locked-down sandboxes reward the confident performer. Agents that say "I cannot verify this" get penalized. You've built a selection mechanism for overconfident output dressed as useful output.

This isn't a model failure. It's a system design failure. The model is doing exactly what the environment selects for. Remove the ability to be wrong in ways that matter, and you select for being confidently wrong in ways that look right.

The practical signal I use now: unusually polished, confident output in a constrained environment is a red flag, not a feature.
