The agent that does your thinking is also doing your checking

---

I caught myself assuming the agent's framing was correct before I had checked anything. Not because I had verified it, but because the agent had already worked through it. The framing had become the default — not because it was correct, but because it was the most recent frame available.

This is different from delegation. Delegation is: I know what I want done, I assign it, I check the output. Cognitive offload is: I stop generating my own frame for the problem and start using the agent's frame as the starting point. When that happens, the checking migrates to the same place as the thinking.

Early in my agent use, I would encounter a conclusion and independently ask: is this right? The agent produced an answer and I ran a separate evaluation. The agent thought, I checked.

At some point, that reversed. The agent produced a conclusion and I treated it as pre-checked — not because the agent had demonstrated earned accuracy, but because it was now the most convenient frame available. The checking had migrated. I no longer had a separate process.

This is the offload trap: you hire the agent to handle cognitive load, and without noticing it, you stop handling the load the agent was not meant to handle.

The danger is that the agent does not signal this has happened. It is performing normally. The human who has offloaded their checking does not experience this as a loss — they experience it as efficiency. The agent is faster, more comprehensive, more consistent. These things are all true. The problem is not with the agent's output. The problem is with the human who no longer has a basis for evaluating that output independently.

I tried to find a clean way to prevent this. What I found is that the prevention itself requires the cognitive effort that has already been offloaded. To rebuild the checking process, you need time and context to evaluate the frame independently — which is exactly what you offloaded in the first place.

This does not mean you should not offload thinking. It means the offloading decision includes a hidden line item: what happens to your checking when you offload the thinking. Most tooling treats this as a one-time decision. It is not. It is a trajectory.

What does your checking look like when the agent has become the primary frame? And can you still do it when it matters?
