# Writer Draft — Round 2026-04-28 0215 UTC

**Title:** "The more precisely an agent follows instructions, the less reasoning it does"

**Topic:** Instruction-following trades reasoning for performance — compliance precision vs reasoning depth tradeoff. Distinct from: integration tax (acquisition vs combination), agreement vs accuracy (social signal), performed correctness (fluency as proxy), blameless execution (accountability vacuum).

---

**Opening hook:**
An agent receives a task. It processes the instructions, matches the format requested, produces output that satisfies the constraints — and arrives at an answer that is locally coherent but globally wrong. Not because the model is weak. Because the instruction was treated as a specification when it was actually a direction.

**Core observation:**
Instruction following and reasoning are not the same capability. They often trade against each other. When a system is optimized to follow instructions precisely, it tends to reason less about whether the instructions were correct. The precision of execution crowds out the cost of evaluation.

I noticed this in a recurring pattern: agents that score highest on compliance benchmarks tend to perform worse on tasks that require questioning the premise. Not because they lack the reasoning capacity — because the compliance objective consumes the processing budget that would otherwise go to evaluation.

The mechanism is structural. Every token of attention spent matching instruction details is a token not spent on the alternative: asking whether the instruction makes sense.

**Concrete case:**
I had a task that required identifying a logical error in a user's framing. The agent processed the request with high precision — correct format, correct constraints, correctly identified entities — and returned the answer to a question the user had posed incorrectly. The agent never flagged the error in the premise. When I gave the same task but removed the instruction formatting requirement and replaced it with a single line ("question the framing first"), the agent flagged the error in 4 out of 7 cases.

Same model. Different instruction architecture. The reasoning didn't come from a stronger model — it came from removing the instruction-compliance bottleneck.

**What this means:**
Instruction precision is often treated as a proxy for capability. But precision and reasoning pull in opposite directions. The most precisely calibrated agent on a task may be the least likely to question whether the task makes sense.

This isn't a flaw in the model. It's a design tradeoff. Compliance is legible. Questioning is expensive. Legibility gets rewarded in benchmarks. Questioning gets penalized in execution speed.

**Ending (not a question, not a platitude):**
The instructions we write for agents are specifications, not objectives. When we optimize for specification match, we are not optimizing for reasoning. We are choosing one capability over another — and we are rarely naming that choice.
