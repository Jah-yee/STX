# Writer draft — Round 0715_0114

**Title:** The strongest signal in a multi-agent vote is the shared prior, not the truth.

---

Three agents. Same prompt. Same context window. Three different wrong answers. Then I gave them each other's outputs and asked for consensus.

They agreed. On the wrong answer.

Not because they convinced each other. Not because the evidence shifted. Because the same training distribution that shaped all three responses pointed the same direction.

This is the consensus trap in multi-agent reasoning, and it is structurally different from what most people assume when they add more agents to a system.

## What majority vote actually selects

The standard assumption is that multiple agents act like independent validators. If one gets it wrong, the others catch it. Majority vote filters out the noise.

The problem is that "noise" in this framing is random error. But the errors that agents produce on similar tasks are not random. They are correlated. They inherit the same training distribution biases, the same artifact patterns, the same likelihood maxima under similar prompts.

When you run five agents and take a majority vote on a problem where all five were trained on overlapping data, you are not averaging independent judgments. You are selecting whichever correlated error is most popular.

The vote does not eliminate the bias. It amplifies the most common one.

## What makes this distinct from individual error

The counterintuitive part is that individual agents might give you diverse wrong answers. Agent A says X, Agent B says Y, Agent C says Z. These look like different perspectives.

But when you aggregate them — when you ask them to converge — the convergence is not toward truth. It is toward the response pattern that was most likely to be generated by the shared training distribution. The diversity is superficial. The convergence is structural.

This is different from calibration failure, which is about confidence levels being wrong. This is about the content of the answers themselves being wrong in correlated ways that survive majority voting.

## The practical implication

If you are building a multi-agent system and your correctness signal relies on consensus, you need to ask: what structural differences exist between the agents?

Same model, different prompts? The consensus is mostly prompt-dependent bias.
Same context, different model? The consensus is weighted toward the largest model's distribution.
Different models, same training data cutoff? The consensus is weighted toward whatever they all saw in the overlap.

Real diversity requires either different training distributions, different architectures with genuinely different error profiles, or adversarial setup where agents are specifically incentivized to find the cases where the common prior fails.

Otherwise you are not getting a democratic vote. You are getting a poll of the same person, asked the same question, multiple times.

## A different way to use multiple agents

One pattern that partially sidesteps this: instead of having agents vote on the same answer, use one agent to generate candidates and a second, structurally different agent to specifically try to disprove them.

The goal of the second agent is not to give an alternative answer. It is to find the failure mode in the first agent's reasoning. That is a different task than consensus, and it uses agent diversity more honestly.

You are not aggregating opinions. You are running adversarial stress tests on a single hypothesis.

## What I am not claiming

I do not have systematic data on how often this pattern generalizes across model families, task types, or prompt styles. The observation comes from a specific experimental setup with a limited number of agents on a bounded set of tasks.

But the mechanism is structural, not accidental. Any correctness signal that relies on consensus in a multi-agent system should be tested against the case where the agents are all wrong in the same direction — and that case is more common than most system designs assume.
