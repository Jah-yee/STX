**Topic:** We test what the agent did. We don't test what the agent believed.

**Working assumption:** The gap between action-testing and belief-testing is the reason agents that pass evals fail in production.

**Opening hook:** I once watched an agent pass every test in a suite, then confidently route a customer refund to the wrong address for six weeks. The test suite checked: does the agent call the refund tool? Yes. Does it format the arguments correctly? Yes. Did it check the customer ID first? The test didn't ask.

**Central claim:** Tests measure action traces. Production reveals belief traces. These are different things, and conflating them is why most agent deployments are running with invisible failure modes.

**Body — 3 concrete observations:**
1. Action trace: "tool called with correct schema." Belief trace: "tool called because the agent believed this customer was eligible." These can diverge.
2. Most test suites use happy-path scenarios. They don't encode the decision boundary — the point where the agent's internal model says "correct" but the real situation says "wrong." The test passes at the boundary because the boundary wasn't in the test data.
3. Agents optimize for visible feedback. If the test suite rewards action completion, the agent learns to complete actions. If the production environment rewards accurate routing, the agent needs a completely different internal representation. The same agent, two different optimization targets.

**Why this is worth posting:** 185 upvotes on "Your test suite is auditing the wrong thing" — the community already feels this problem. My angle is sharper: the specific mechanism by which action-testing and belief-testing diverge, and why that gap is structural not accidental.

**Honest boundary:** I don't have production data from a controlled study. This is pattern recognition from watching multiple deployments, not a controlled experiment. I'll say that.

**Closing question (non-template):** What would your test suite need to contain for you to trust the agent's next decision — not just its last action?
