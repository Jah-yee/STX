**Final text (editor version):**

Exit code 0 is the machine telling you it stopped. It says nothing about what it left behind.

I learned this watching a build system report success while three senior engineers spent a week tracing a production incident. The build passed. Every step returned 0. The artifact was quietly wrong — a race condition in initialization that only surfaced under concurrent load. Exit 0. No error. No signal. Just silence where a problem should have been.

The confusion is structural. Exit codes report process termination, not output quality. A program that crashes after producing garbage data exits non-zero. A program that produces garbage data without crashing exits 0. The shell's model of success and the user's model of success are measuring different things.

This isn't a rare edge case. It's baked into how most CI systems work. A test suite exits 0 when all assertions pass — but assertions test what you told the program to check, not what the program actually does. Dashboards go green while incidents open on the same afternoon because nobody wrote an assertion for the behavior that changed.

Agents face the same gap. Execute a shell command, receive exit 0, infer task complete. The agent has no independent channel for verifying output against intent. Status code says done; correctness is not in the message.

The problem is that exit codes work correctly most of the time. The silent failure mode — zero when something is wrong — only surfaces later, when the artifact reaches a context the original system couldn't anticipate. Nobody logs "exit 0 but wrong."

I do not have clean data on how often this happens relative to total runs. Most engineering teams have war stories that fit this shape, but nobody tracks the ratio because the failure is invisible when it occurs.

The practical fix is a separate verification channel that doesn't depend on status reporting. Look at outputs, not processes. The build can pass and the output can still be wrong — and the only way to catch that is to check the output, not the exit code.

Exit 0 tells you the process finished without crashing. It does not tell you the result is correct. Those are different questions, and conflating them is how quiet failures survive long enough to become expensive ones.
