> **文档版本**：1.0
> **创建时间**：2026-04-16

> **状态**：正式运行

## 1. 工作定位（Purpose）

### 1.1 核心职责

本 cron job 作为系统自动化清道夫，定时执行磁盘空间清理任务，核心目标：

- **空间回收**：释放被废弃文件占用的磁盘空间
- **预防性维护**：在磁盘空间耗尽前主动清理，避免服务中断
- **资源优化**：保持 `/home`、`/tmp`、`/var/log` 等目录的健康状态

### 1.2 在系统中的角色

| 定位 | 说明 |
|------|------|
| **预防性维护** | 定期运行，在问题发生前清理，而非等告警触发 |
| **主动性清理** | 不仅清理已知 pattern，还主动扫描大文件、旧文件 |
| **辅助工具** | 补充系统管理员的日常巡检，非替代关系 |

### 1.3 为什么需要它

- Linux 系统长期运行后，`/tmp`、`/var/tmp`、`/log` 等目录会积累大量临时文件
- 用户目录（`/home`）可能藏有巨型缓存、日志、压缩包
- 没有自动化清理，磁盘最终会写满，导致服务故障、cron 任务失败
- 人工清理费时费力，且容易遗漏
- 本框架通过**安全优先的多轮策略**，在最小风险下最大化清理效果

## 2. 安全边界（Safety Boundary）

### 2.1 绝对禁止删除的目录和文件

以下路径和文件**在任何情况下、任何轮次均不得删除**：

```bash
# 系统关键目录

/bin                        # 系统二进制
/sbin

/lib64
/usr                        # 系统资源
/boot                       # 启动文件
/dev                        # 设备节点
/proc                       # 进程信息
/sys                        # 系统信息
/run                        # 运行时数据
/lock                       # 锁文件

# 关键配置文件
/etc/fstab
/etc/passwd
/etc/shadow
/etc/group
/etc/sudoers
/etc/ssh/sshd_config
/etc/crontab
/etc/cron.d/
/etc/cron.daily/
/etc/cron.hourly/
/etc/cron.weekly/
/etc/cron.monthly/

# 日志（由 logrotate 处理，不得手动大范围删除）
/var/log/lastlog
/var/logwtmp
/var/log/btmp
/var/log/private/         # 私有日志，禁止访问

# 用户数据（除非明确确认是缓存/临时文件）

/var/lib/postgresql/
/var/lib/mongodb/
```

### 2.2 删除前必须满足的条件

删除操作必须满足**所有**以下条件：

1. **文件年龄 ≥ 阈值**：临时文件至少 `7` 天未被访问（可配置）
2. **不属于活跃进程**：文件描述符未被任何运行中进程占用
3. **不在重要路径**：不在黑名单（见 2.1）之内
4. **符合删除 pattern**：在白名单 patterns 中，或被评估为可安全删除
5. **权限合法**：当前用户有删除权限，不得跨权限删除其他用户文件（除非 `root`）
6. **不是符号链接**：符号链接单独处理，不递归跟随
7. **不是正在使用的包管理器文件**：如 `apt`、`yum`、`dnf` 正在操作的文件

### 2.3 需要人工审批的场景

以下情况**必须暂停删除**，等待人工确认：

| 场景 | 阈值/条件 |
|------|-----------|
| 单个文件大小 > `10GB` | 触发审批 |
| 单次运行预期删除总量 > `50GB` | 触发审批 |
| 扫描到数据库文件（`*.sql*`, `*.db`） | 强制暂停 |
| 扫描到用户主目录下的压缩包（`*.zip`, `*.tar.gz`）> `1GB` | 触发审批 |
| 触发黑名单关键词（如 `backup`, `important`, `critical`） | 强制暂停 |
| 系统磁盘使用率 > `95%` | 降级为仅报告模式 |
| 上次运行报告了异常 | 本次仅做安全扫描，不删除 |

### 2.4 不可恢复风险提示

> ⚠️ **警告**：本框架执行的删除操作为**不可逆操作**。一旦文件被删除，数据将无法恢复。请确保：
>
> 1. **备份优先**：对于重要数据，先备份再清理
> 2. **增量执行**：先小范围测试，确认无误后再扩大范围
> 3. **日志追溯**：所有删除操作均记录日志，支持事后审计
> 4. **并行保护**：关键路径扫描使用只读模式验证

## 3. 三省六部架构

本框架借鉴古代三省六部制度，将磁盘清理任务分解为六个专业部门，通过 subagent 并行/串行协作完成。

### 3.1 组织架构图

```
                    ┌─────────────────────────┐
                    │       尚书省            │
                    │   （主调度者）           │
                    │  任务分发 · 结果汇总     │
                    └──────────┬──────────────┘
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
          ▼                    ▼                    ▼
   ┌────────────┐      ┌────────────┐      ┌────────────┐
   │    吏部    │      │    户部    │      │    兵部    │
   │  扫描发现  │ ───▶ │  评估可删  │ ───▶ │  执行删除  │
   └────────────┘      └────────────┘      └────────────┘
          │                    │                    │
          └────────────────────┼────────────────────┘
                               │
                    ┌──────────▼──────────────┐
                    │       刑部              │
                    │    复核验证             │
                    └──────────┬──────────────┘
                               │
                    ┌──────────▼──────────────┐
                    │       工部              │
                    │    记录报告             │
                    └─────────────────────────┘
```

### 3.2 各部职责详解

#### 尚书省（主调度者）

**职责**：
- 接收 cron 触发信号，按时启动清理任务
- 将任务分发至吏部（扫描）和户部（评估）
- 协调三轮执行时序（安全模式 → 中等风险 → 深度清理）
- 汇总各部结果，决定是否进入下一轮
- 超过阈值时暂停，等待人工审批
- 触发最终报告发送给工部

**输出**：`dispatch_report.json` — 本轮任务分发状态

#### 吏部（扫描发现）

**职责**：
- 扫描指定目录，发现候选文件
- 按 pattern（安全模式 / 中等风险 / 深度）筛选文件
- 过滤黑名单目录和文件
- 生成文件清单（含路径、大小、修改时间、访问时间）
- 识别大文件（> 阈值）和旧文件（> 天数阈值）

**并行策略**：
- 按物理分区并行扫描（如 `/home`、`/tmp`、`/var` 分开）
- 每个子分区一个 subagent，最多 `4` 个并发

**输出**：`scan_report_<round>.json`

```json
{
  "round": 1,
  "timestamp": "2026-04-16T03:00:00Z",
  "scanned_paths": ["/tmp", "/var/tmp"],
  "files_found": 1342,
  "total_size_bytes": 5368709120,
  "files": [
    {
      "path": "/tmp/session_abc123.tmp",
      "size_bytes": 1048576,
      "mtime": "2026-04-09T10:00:00Z",
      "atime": "2026-04-15T02:00:00Z",
      "pattern_matched": "tmp_session_files"
    }
  ]
}
```

#### 户部（评估可删）

**职责**：
- 接收吏部文件清单，逐项评估删除风险
- 检查文件是否属于活跃进程（通过 `/proc` 判断文件描述符）
- 检查是否为系统关键文件（路径白名单 + 关键词扫描）
- 识别用户重要文件（检测文件名中的 `backup`、`important` 等词）
- 计算每条记录的"安全分数"（0-100）

**安全分数权重**：
| 因素 | 权重 | 说明 |
|------|------|------|
| 文件年龄 | 30% | 越老越安全 |
| 所在目录 | 25% | `/tmp` > `/var/tmp` > `/home` |
| 文件大小 | 15% | 小文件更安全 |
| 文件名风险词 | 20% | 有风险词则扣分 |
| 进程占用 | 10% | 被占用则不可删 |

**输出**：`evaluation_report_<round>.json`

```json
{
  "round": 1,
  "total_candidates": 1342,
  "safe_to_delete": 1200,
  "needs_review": 42,
  "protected": 100,
  "files": [
    {
      "path": "/tmp/session_abc123.tmp",
      "size_bytes": 1048576,
      "safety_score": 95,
      "decision": "safe_to_delete",
      "reason": "Age>7d, /tmp/, small file, no risk keywords"
    }
  ]
}
```

#### 兵部（执行删除）

**职责**：
- 接收户部的"可删除"清单
- 对每批文件执行删除操作
- 记录每条删除的成败状态
- 处理删除失败（权限、文件已消失等）
- 遵守删除速率限制（避免 I/O 突刺影响系统）

**执行原则**：
- **Dry-run 优先**：先记录计划删除的文件，交尚书省审批后再执行
- **批量执行**：每批 `100` 个文件，间隔 `0.5s`
- **权限检查**：非 root 不得删除他属文件

**输出**：`deletion_report_<round>.json`

```json
{
  "round": 1,
  "total_requested": 1200,
  "deleted": 1198,
  "failed": 2,
  "space_reclaimed_bytes": 5242879452,
  "failures": [
    {
      "path": "/tmp/locked_file.tmp",
      "reason": "Permission denied"
    }
  ]
}
```

#### 刑部（复核验证）

**职责**：
- 兵部执行完成后，复核删除结果
- 验证文件确实已被删除
- 检查系统健康状态（磁盘 I/O、进程数是否有异常）
- 抽查删除文件，确认不是系统关键文件
- 对比删除前后磁盘使用率

**输出**：`verification_report_<round>.json`

```json
{
  "round": 1,
  "deletion_verified": 1198,
  "deletion_failed_but_marked_deleted": 0,
  "system_healthy": true,
  "disk_usage_before_pct": 78,
  "disk_usage_after_pct": 71,
  "space_reclaimed_actual_bytes": 5242879452
}
```

#### 工部（记录报告）

**职责**：
- 汇总各部报告，生成最终清理报告
- 记录完整操作日志（日、时、分、操作用户）
- 生成结构化报告（JSON + Markdown）
- 将报告推送至监控渠道（飞书/日志文件）
- 维护历史统计（周/月趋势图数据）

**输出**：`final_report_<timestamp>.md` + `final_report_<timestamp>.json`

### 3.3 审批流程

每轮遵循以下审批链：

```
吏部扫描 ──▶ 户部评估 ──▶ 尚书省审批 ──▶ 兵部执行 ──▶ 刑部复核 ──▶ 工部存档
     │           │              │              │             │
     └───────────┴──────────────┴──────────────┴─────────────┘
                          尚书省决定
                          │
              ┌────────────┴────────────┐
              │                         │
         ✅ 继续下一轮               ⚠️ 暂停待批
         (安全分数 > 阈值)            (需人工审批)
```

**自动审批条件**（安全分数 > 80，无需人工）：
- Round 1（安全模式）：自动批准
- Round 2（中等风险）：安全分数 > 85 才自动批准
- Round 3（深度清理）：安全分数 > 90 才自动批准

## 4. 目标（Goals）

### 4.1 清理空间目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 单次运行清理量 | `≥ 5GB` | 每次至少清理 5GB |
| 单次运行最高清理量 | `≤ 50GB` | 超过需人工审批 |
| 周累积清理量 | `≥ 20GB` | 一周内累计清理 20GB |
| 月累积清理量 | `≥ 80GB` | 一月内累计清理 80GB |
| 磁盘使用率目标 | `< 75%` | 清理后保持 75% 以下 |

### 4.2 安全性目标

| 指标 | 目标值 | 备注 |
|------|--------|------|
| 误删率 | `< 0.01%` | 每万次操作不超过 1 次误删 |
| 系统文件误删 | `0` | 系统文件误删必须为零 |
| 用户主动文件误删 | `0` | 用户主动创建的文档不得误删 |
| 审批通过率（自动） | `≥ 90%` | 90% 的删除请求自动审批通过 |
| 人工审批场景触发率 | `< 10%` | 大多数清理无需人工介入 |

### 4.3 效率目标

| 指标 | 目标值 |
|------|--------|
| 单次运行总时长 | `≤ 30 分钟` |
| 扫描阶段 | `≤ 10 分钟` |
| 评估阶段 | `≤ 5 分钟` |
| 删除阶段 | `≤ 15 分钟` |
| 验证阶段 | `≤ 3 分钟` |

## 6. 三轮执行策略

每轮包含完整链路：**发现 → 评估 → 审批 → 删除 → 复核**。

### Round 1：安全模式（Safety Mode）

**目标**：清理已知可安全删除的文件，风险最低

**扫描范围**：
- `/tmp` — 临时文件
- `/var/tmp` — 临时文件
- `/tmp/*.log` — 旧日志
- `~/.cache/` — 用户缓存（可选）
- 已知 pattern：`*.tmp`、`*.cache`、`*.bak`、`core.*`（core dump）

**删除条件**（同时满足）：
- 文件年龄 > `7` 天
- 文件大小 < `100MB`
- 文件名不包含风险词

**预期清理量**：`5 ~ 15 GB`

**自动批准阈值**：安全分数 > 80 → 自动批准

---

### Round 2：中等风险模式（Moderate Mode）

**目标**：扫描并清理较大文件和较旧文件

**扫描范围**：
- 所有 Round 1 剩余文件
- 扫描所有 `/tmp`、`/var/tmp` 中 > `100MB` 的文件
- 扫描 `/home/*/Downloads/` 中 > `30` 天未访问的文件
- 扫描 `/var/log/` 中 > `30` 天的归档日志

**删除条件**：
- 文件年龄 > `14` 天
- 文件大小 `100MB ~ 1GB`
- 已有完整文件名风险词过滤

**额外验证**：
- 检查文件是否被任何活跃进程占用
- 大于 `500MB` 的文件需二次确认文件名 pattern

**预期清理量**：`10 ~ 20 GB`

**自动批准阈值**：安全分数 > 85 → 自动批准

---

### Round 3：深度清理模式（Deep Mode）

**目标**：进一步分析剩余文件，识别可清理但需要判断的项目

**扫描范围**：
- 所有剩余未处理文件
- 深度分析 `/home` 下的巨型缓存目录
- 扫描重复文件（相同 checksum 的文件保留一份）
- 分析日志文件压缩可能性（未压缩的旧日志）

**删除条件**：
- 文件年龄 > `30` 天
- 或：文件大小 > `1GB` 且不在黑名单目录
- 或：被识别为重复文件（保留最新一份）

**额外验证**：
- 对每个待删文件执行完整性检查（文件头校验）
- 超过 `2GB` 的文件必须人工审批
- 任何触发黑名单关键词的文件必须人工审批

**预期清理量**：`5 ~ 10 GB`

**自动批准阈值**：安全分数 > 90 → 自动批准
